**التاريخ:** 18 أكتوبر 2026 · **الأولوية:** متوسطة · **التقدير:** يوم إلى يومان عمل

---

## 0. الملخص التنفيذي

نريد توسيع لوحة إحصائيات مركز المباراة لتعرض **28 رقمًا بدل 11** من المصدر الحالي نفسه
(ESPN `summary.boxscore.teams[].statistics`) **بلا أي مزوّد جديد ولا تكلفة**، مع أربع
إضافات بصرية صغيرة. **الملعب الحالي (الإطار الأخضر + شريط الأحداث + ملعب التشكيلة) يبقى
كما هو تمامًا**؛ لا نلمس منطقه ولا تخطيطه.

## 2. قواعد غير قابلة للتفاوض

1. **المصدر الحالي فقط.** لا استدعاءات جديدة، لا مزوّد مدفوع، لا نسخ أو كشط من أي موقع آخر.
2. **لا اشتقاق.** «خارج المرمى» لا يُحسب بطرح «على المرمى» من الإجمالي، ولا أي قيمة مشتقة
   من قيمتين (الاختبار الحالي في `test-match-center-php.mjs` يحرس هذا — أبقه).
3. **الغياب غياب.** القيمة `null` تُعرض «لا رقم من المصدر»، ولا تُستكمل صفرًا، والصف الذي
   لا قيمة فيه للطرفين لا يُرسل أصلًا (سلوك `mc_read_statistics` الحالي — أبقه).
4. **الملعب لا يُمس.** `.mc-pitch-frame` و`.mc-pitch-events` و`.mc-pitch-lineups` ومنطقها
   في `MatchCenterVisuals.tsx` تبقى كما هي؛ الإضافتان داخلها (العدّادات واسم المركز)
   إضافة عناصر فقط بلا تغيير في البنية أو السلوك.
5. **قاعدة المواجهات القائمة تبقى** (آخر 3 مواجهات مكتملة — `mergeH2h(..., 3)` البند 8).
   التصور يعرض 5 صفوف للتوضيح فقط؛ العدد الفعلي يتبع القاعدة الحالية.

## 3. التغييرات المطلوبة — ملفًا ملفًا

### 3.1 `match-center.php` — توسيع `MC_STAT_LABELS` (السطور ~1140–1152) من 11 إلى 28

الأسماء الـ17 الجديدة كلها مؤكدة في `espn-summary-probe.json → results[].rawStatNames`.
أبقِ المفاتيح الـ11 الحالية بتسمياتها، وأضف الباقي بهذه التسميات (الترتيب هنا للقراءة؛
الترتيب الفعلي للعرض يحدده `STAT_GROUPS` في الواجهة):

| المفتاح | التسمية العربية | الوحدة |
|---|---|---|
| `possessionPct` | الاستحواذ | `%` |
| `totalPasses` ★ | إجمالي التمريرات | |
| `accuratePasses` ★ | التمريرات الصحيحة | |
| `passPct` | دقة التمرير | `%` |
| `totalShots` | التسديدات | |
| `shotsOnTarget` | على المرمى | |
| `blockedShots` | تسديدات تم اعتراضها | |
| `shotPct` ★ | نسبة التسديد على المرمى | `%` |
| `penaltyKickShots` ★ | ركلات جزاء — محاولات | |
| `penaltyKickGoals` ★ | ركلات جزاء — أهداف | |
| `totalCrosses` ★ | العرضيات | |
| `accurateCrosses` ★ | العرضيات الدقيقة | |
| `crossPct` ★ | دقة العرضيات | `%` |

(★ = جديد، 17 مفتاحًا.)

**تحقّق قبل اعتماد التسميات (مهم):**
- افتح `results[].statistics` في المسبار وتأكد أن قيم `*Pct` تصل كأعداد من 0 إلى 100
  (مثل `66`) لا كسور (`0.66`)؛ `mc_num($stat['value'] ?? displayValue)` يبقى كما هو إن كانت كذلك.
- تأكد من معنى `shotPct` من قيمه الفعلية مقابل `shotsOnTarget/totalShots`. إن لم يطابق،
  غيّر التسمية إلى «نسبة التسديد» العامة ولا تخمّن.

### 3.2 `website/src/lib/match-center.mjs`

**أ) `STAT_GROUPS` (السطر ~1245): من 3 مجموعات إلى 6، بهذا الترتيب والمفاتيح:**

```js
export const STAT_GROUPS = [
  { id: 'possession-passing', label: 'الاستحواذ والتمرير',
    keys: ['possessionPct', 'totalPasses', 'accuratePasses', 'passPct'] },
  { id: 'shots', label: 'التسديد',
    keys: ['totalShots', 'shotsOnTarget', 'blockedShots', 'shotPct', 'penaltyKickShots', 'penaltyKickGoals'] },
  { id: 'build-up', label: 'بناء الهجمة',
    keys: ['totalCrosses', 'accurateCrosses', 'crossPct', 'totalLongBalls', 'accurateLongBalls', 'longballPct', 'wonCorners'] },
  { id: 'defense', label: 'الدفاع',
    keys: ['totalTackles', 'effectiveTackles', 'tacklePct', 'interceptions', 'totalClearance', 'effectiveClearance'] },
  { id: 'goalkeeping', label: 'حراسة المرمى', keys: ['saves'] },
  { id: 'discipline', label: 'الانضباط',
```

- `STAT_GROUP_FALLBACK` و`groupStatistics` و`compareStatRow` تبقى بلا تغيير — المجموعة
  التي لا يصلها أي صف لا تُعرض (السلوك الحالي).
- لاحظ أن `wonCorners` انتقلت من «الدفاع والانضباط» إلى «بناء الهجمة».

**ب) خريطة أسماء المراكز بالعربية** (بجوار `PITCH_ROLES` السطر ~1536) — دالة مُصدَّرة
`positionLabelAr(code)` تعيد `null` لأي رمز غير معروف (فتعرض الواجهة الرمز وحده كما اليوم):

| الرمز | التسمية |
|---|---|
| `G` | حارس المرمى |
| `CD` / `CD-L` / `CD-R` | قلب دفاع / قلب دفاع أيسر / قلب دفاع أيمن |
| `LB` / `RB` | ظهير أيسر / ظهير أيمن |
| `DM` / `DM-L` / `DM-R` | وسط دفاعي / وسط دفاعي أيسر / وسط دفاعي أيمن |
| `CM` / `CM-L` / `CM-R` | وسط / وسط أيسر / وسط أيمن |
| `LM` / `RM` | جناح أيسر / جناح أيمن |
| `AM` / `AM-L` / `AM-R` | وسط هجومي / وسط هجومي أيسر / وسط هجومي أيمن |
| `F` / `CF` / `CF-L` / `CF-R` | مهاجم / مهاجم / مهاجم أيسر / مهاجم أيمن |

أضف اختبارًا يضمن أن كل رمز داخل `PITCH_ROLES` له تسمية في الخريطة.

**ج) مجمل المواجهات** — دالة مُصدَّرة `headToHeadSummary(entries, homeName, awayName)`
تعيد `{ homeWins, draws, awayWins, total }` أو `null`:
- تعمل على **القائمة نفسها** التي تعيدها `headToHeadFor(match, snapshot, status)` (لا تجلب شيئًا جديدًا).
- تنسب الفوز بمطابقة `entry.home` / `entry.away` مع اسمي الفريقين كما تُعرض الصفوف اليوم.
- إن تعذّرت نسبة **أي** صف (اسم لا يطابق أحد الطرفين) تعيد `null` ولا يُعرض السطر — لا تخمين.

### 3.5 `website/src/components/MatchCenterStatGroups.tsx`

- **رأس كل مجموعة:** شعار المضيف · العنوان · شعار الضيف (أعد استعمال `Crest` بـ

- **شريط الاستحواذ البارز** فوق المجموعات: يُعرض فقط إذا كانت قيمتا `possessionPct`

## 4. حالات الحافة التي يجب أن تُختبر

| الحالة | السلوك المطلوب |
|---|---|
| قبل المباراة، `statistics === null` | لا شريط استحواذ، لا عدّادات، لا صندوق «ما لا يرسله المصدر»؛ باقي الصفحة كما اليوم |
| المصدر يرسل جهة واحدة فقط لصف ما | القيمة الموجودة تُعرض، والأخرى «لا رقم من المصدر»، والشريط للطرف الموجود فقط |
| صفر حقيقي (`0` من المصدر) | يُعرض `0` ولا يُعامل كغياب |
| مجموعة بلا أي صف وارد | تُخفى كاملة (مثلًا «حراسة المرمى» إن غابت `saves`) |
| اسم إحصائية جديد غير معروف | يبقى في `source-other` كما اليوم — لا يُرمى |
| اسم فريق في المواجهات لا يطابق الطرفين | سطر المجمل يُخفى بالكامل |
| رمز مركز غير موجود في الخريطة | يُعرض الرمز وحده كما اليوم |
| قيم `*Pct` خارج 0–100 أو غير رقمية | تُعامل `null` (لا تُقصّ ولا تُصحَّح) |
