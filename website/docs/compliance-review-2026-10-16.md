## ما أُصلح

1. **القياس والإعلانات:** استُخدم كود GA4 وأدسنس المعتمد نفسه في صفحة الموسم وصفحتي متابعة سيتي وروما. لا تعديل أو إعادة ترتيب لكود GA4 القائم. فحص الحفظ قارن 43 صفحة HTML متتبعة في Git مع HEAD، منها 42 تحمل GA4: صفر تغييرات في شيفرة GA4 أو عدد محملات أدسنس السابقة أو نص التذييل القانوني. المعرفان ثابتان، ولا متتبع أو مكتبة إضافية. `ads.txt` بقي كما هو، ولم يُوسّع استثناء الإعلانات.
2. **التنقل:** إضافة رابط `/match-analysis/` نفسه داخل قائمة الموسم إلى جانب `#reports`، بدل إخفاء وجهة القسم خلف رابط الجولة فقط. بقيت الروابط الثلاثة تحت موسم 2026/2027 ثم الجولة الثانية. لم يتغير اختبار التنقل الأصلي لمعالجة الفشل.
3. **حدود PHP:** أُعيد `standings.php` ومصدره إلى نسخة HEAD، وأُزيل تمديد قائمتها المسموحة. لا فروق في أي PHP أو `channels.json` أو `admin-dashboard/`. جداول الدوريين الفرنسي والإيطالي كاملة ومؤرخة لكنها ثابتة؛ لا طلبات متصفح لتحديثهما ولا تلميح إلى ترتيب لحظي. التحديثات السابقة لدوري الأبطال والإنجليزي والإسباني باقية.
4. **الاختبارات والميزة الملغاة:** أُعيد اختبار PHP الأصلي إلى HEAD أيضًا. استُبدل فقط اختبارا توسيع الدوريين المضافان مع الميزة الملغاة باختبار حدّ أقوى: جدول كامل، تاريخ واضح، وصفر طلبات PHP بعد مرور دورة التحديث. لا تعطيل لاختبار قائم أو تخفيف لفحوص SEO/التنقل.
5. **المصادر وSEO:** مصادر الصفحات الخمس الجديدة في `website/src/pages/analysis/`. النصوص والبيانات المرجعية في `website/src/content/`. المرجع الوحيد لـ SEO هو `website/src/seo.ts`؛ يُصدّر عبر بناء SSR ويطبّق أثناء البناء. الملفات المقابلة في `legacy/` لقطات مشتقة آليًا لدعم مسار النشر واختبارات المصادر القائمة، وليست مصدرًا آخر للتحرير. صفحتا أتلتيكو القديمتان تبقيان في `legacy/` مع مزامنة head من المرجع المركزي نفسه. لا تحرير يدوي لملفات HTML المنشورة.
6. **الهوية:** لم تُضف هوية أو هاتف أو نطاق حرفي إلى عارض البطاقات أو مولد الصور؛ الهوية تُقرأ من config عبر بناء SSR. بقي مصدر النطاق المشترك القائم `site.mjs` وإعادة تصديره عبر `config.ts` دون إنشاء مصدر هوية منافس. لم تتغير الأسعار أو نصوص DMCA أو إخلاء المسؤولية.
7. **الصور والحقوق:** لا صور مباريات أو أصول صحفية. الرموز المستخدمة في الصفحات السبع تصاميم حرفية هندسية أصلية، وليست شعارات الأندية الرسمية. أزيلت صور PNG الأربع المضافة سابقًا ذات الترخيص غير الموثق. صور العرض WebP، وأصول العمل القابلة للتحرير تحت `src/assets/analysis-badges/`. كل صورة لها أبعاد ونص بديل، ورموز البطاقات الستة تحت الطية تستخدم lazy loading. صورة مشاركة PNG أصلية مستقلة 1200×630 لكل واحدة من الصفحات السبع. لم يُغيّر النص القانوني السابق المنسوب إلى مصدر الشعارات؛ أضيف توضيح مستقل للرموز الأصلية المعروضة.
8. **البيانات المنظّمة:** تطابق WebPage العناوين والأوصاف المركزية. BreadcrumbList مطابق للتنقل المرئي وينتهي بالصفحة الحالية. قائمة البطاقات تُشتق من بياناتها نفسها ولها @id وإحالات إلى معرفات الصفحات. صحّح اختبار جديد اختلاف إجابات FAQ القديمة عن النص الظاهر بنسخ الإجابة المرئية إلى JSON-LD، دون تغيير النص المرئي أو القانوني. لم يُضف حدث جديد أو Article بمؤلف غير معروف، ولا أسعار أو تقييمات تجارية أو كيانات موقع Organization/WebSite مكررة. بقي حدث أتلتيكو المعتمد في صفحته وحدها وصفحة المتابعة تشير إليه؛ لم تُخمّن حقائق حدث جديدة.
9. **الاكتشاف:** لا تغيير للسلاجات، ولا حاجة إلى تحويلات. الروابط الداخلية وصفية، والمباريات مرتبطة بقسم الموسم وببعضها عبر مسار التنقل. تحديث خريطة الصفحات القديمة مؤرخ بالتغييرات الفعلية، لا بتغيير تاريخ شكلي.

## إعادة إنتاج الأصول

بعد `npm run build`:

```sh
node website/scripts/generate-analysis-og.mjs
node website/scripts/generate-analysis-badges.mjs
npm run build
```

مولد المشاركة يستعمل Playwright/Chromium الموجودين بالفعل وخطًا محليًا؛ مولد الرموز يستعمل ImageMagick وخط DejaVu على جهاز التطوير فقط. لا تحميل صور أو خطوط خارجية للزائر، ولا مكتبة npm جديدة.

## التحقق

- `npm run typecheck`: ناجح بعد التغييرات.
- `npm run test`: 315 اختبارًا ناجحًا، صفر فشل وصفر تجاوز. استُخدم محرك PHP/WASM المعزول الموثق مسبقًا في README لاختبار PHP، دون إضافة تبعية للموقع أو تغيير ملف قفل.
- `npm run build`: ناجح.
- `npm run test:ui`: 164 اختبارًا ناجحًا، بما فيها اختبارات التنقل الثلاثة التي فشلت قبل الإصلاح (الفحص الكامل: 12.9 دقيقة).
- اختبارات مطابقة إضافية، لا بديلة: metadata من المرجع المركزي، الأكواد الصحيحة مرة واحدة، توافق الأسئلة المرئية، breadcrumb، الصور والأبعاد والصيغ، عدم تحميل خطوط خارجية، ومراجع ItemList.

## ما لا يمكن إثباته من معاينة محلية

- اختبار PHP الحقيقي للمنطق ودورة التخزين والتحقق من الطلبات نجح عبر WASM، لكنه لا يثبت إعداد PHP/cURL أو الاتصال الخارجي الفعلي على استضافة الإنتاج. ملفات PHP لم تتغير.
- وجود محمل أدسنس و`ads.txt` لا يثبت موافقة الحساب أو ملء موضع إعلاني. `data-ad-status="filled"` وإعدادات الإعلانات التلقائية تُراجع على الإنتاج/حساب المالك.
- مراجعة CMP المعتمد وTCF v2.3 والموافقة لزوّار أوروبا، وربط `ad_storage` في GA4، تتطلب إعدادات الحساب وبيئة الزيارات الفعلية. لم تُضف منصة موافقة أو تغير سياسة الخصوصية أو قياسًا قائمًا دون قرار من المالك.
- هذه المراجعة ليست ضمانًا قانونيًا لامتثال الموقع كله ولا ضمان قبول أدسنس أو ترتيب جوجل؛ لا تُنشر قبل موافقة المالك والمراجعة المطلوبة.
