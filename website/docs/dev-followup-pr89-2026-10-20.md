## 1) المطلوب: PR صغير مستقل باسم `fix(seo): guard indexable pages only + coverage assertion`

> **قاعدة حاكمة:** هذا الـPR **لا يلمس أي عنوان ولا وصف ولا سعراً ولا سياسة**، ولا يعدّل أي اختبار قائم. بيانات وحرّاس فقط. أبقِه صغيراً ليُقاس وحده.

### P1 — 🔴 لا تفحص الحرّاس الصفحات `noindex` (يمنع المرحلة 3)

**المشكلة بالأرقام:** `SEO_STRICT=1 npm run build` يفشل بـ**931** مخالفة، **866** منها على **727 صفحة `noindex`** (720 صفحة مباراة + صفحات وظيفية). هذه صفحات لا تُفهرس ولا ترتيب لها؛ فرض «صفر مخالفات» عليها يعني إعادة صياغة مئات العناوين بلا أي عائد ترتيبي — أي أن المرحلة الثالثة تصبح غير قابلة للتحقيق بالتصميم.

**المطلوب:**

1. في `website/scripts/prerender.mjs`: لا تُمرّر المسار إلى الحرّاس إلا إذا كان قابلاً للفهرسة — نفس منطق استثناء 404 الموجود عندك:

```js
const noindex = String(seo.robots ?? "").startsWith("noindex");
if (!noindex) {
  const keywordViolation = assertKeywordInTitle(route, seo.title, seo.primaryKeyword ?? null);
  if (keywordViolation) violations.push(keywordViolation);
  violations.push(...assertTitleShape(route, seo.title));
}
```

2. في `website/scripts/publish-static.mjs`: نفس الشرط على الصفحات القديمة — اقرأ `<meta name="robots">` من الملف قبل فحصه، وتخطَّ ما يبدأ بـ`noindex`.

3. **لا تُخفِ الأرقام:** أبقِ عدّاداً معلوماتياً في أعلى التقرير:

```
# الملخص
- صفحات مرسومة مسبقاً: 775 · قابلة للفهرسة: 81 · noindex: 727
- مخالفات على صفحات قابلة للفهرسة (مانعة): 18
- ملاحظات على صفحات noindex (لا تُحجب البناء): 866
```

**معيار القبول:** بعد التعديل، `SEO_STRICT=1 npm run build` يفشل بـ**18** مخالفة فقط (كلها «العنوان لا يخدم كلمته»)، لا 931. أرفق مخرَج الأمر في وصف الـPR.

### P2 — 🟠 قِس شكل العنوان قبل لاحقة البراند (قرار سياسة، لا صياغة)

**المشكلة:** `assertTitleShape` يقيس العنوان النهائي بعد لصق `| ستريم ماستر برو` (18 حرفاً). النتيجة: **165 من 166** مخالفة «طول» تختفي فوراً عند طرح اللاحقة، والوحيد الطويل فعلاً هو `/live-free.html` (79 حرفاً) وهو `noindex` أصلاً. أي أن الموقع **لا يحوي عنواناً واحداً يتجاوز 60 حرفاً بدون اسم الموقع** — بينما التقرير يوحي بـ166.

كذلك قاعدة «لا براند في العنوان» ليست خطأً تقنياً بل **سياسة**، وقاعدتنا المكتوبة تقول: «عنوان ≈55 حرفاً **بدون** اسم الموقع» — أي أن وجوده في النهاية مسموح. تحويله إلى مخالفة يجعل 40 صفحة مفيدة «مخالفة» بلا سبب.

**المطلوب:**

1. افصل القاعدتين إلى دالتين مستقلتين في `scripts/seo-guard.mjs`:
   - `assertTitleLength(route, title)` — تقيس **الجزء قبل أول `|`** فقط، وترفع مخالفة عند >60 (وتحذيراً عند >55).
   - `noteBrandInTitle(route, title)` — تُعيد **ملاحظة معلوماتية** لا مخالفة مانعة.
2. البراند يظهر في التقرير تحت عنوان «ملاحظات سياسة (غير مانعة)» بعددها الحقيقي (40 على الصفحات المفيدة)، ولا يدخل في عدّاد `SEO_STRICT`.
3. حدّث التعليق أعلى الملف ليقول صراحةً: الطول يُقاس بدون اللاحقة، والبراند سياسة لا خطأ.

**السبب:** بعد هذا التعديل تصبح مخالفات PR-2 **18 عنواناً فقط** بدل 68، وهو ما يقلّل خطر تغيير 41 عنواناً بلا داعٍ.

**معيار القبول:** التقرير يعرض «طول > 60: 0» على الصفحات القابلة للفهرسة، و«براند: 40 (معلوماتي)».

> إن قرّر المالك حذف البراند من العناوين لاحقاً، فهذا قرار PR-2، ولا يُنفَّذ هنا.

### P3 — 🟠 تأكيد أن كل صفحة قابلة للفهرسة مُعلَنة في الخريطة

**المشكلة:** التغطية اليوم مضبوطة (81=81) بالمصادفة الجيدة، لكن `keywordsFor` تُرجع `{ primary: null, intent: "navigational" }` **بصمت** لأي مسار غير معلَن. أضف صفحة غداً ⇒ تدخل الإنتاج بلا كلمة وبلا قصد، ولا حارس ينبّه. هذا يعيد إنتاج المشكلة الأصلية التي أُنشئ الـPR لمنعها.

**المطلوب:**

```js
// في prerender.mjs بعد جمع المسارات
const declared = new Set(Object.keys(KEYWORDS));
const indexableRoutes = routes.filter(r => !String(renderPage(r).seo.robots ?? "").startsWith("noindex"));
const missing = indexableRoutes.filter(r => !declared.has(normalizeRoute(r)));
const extra   = [...declared].filter(r => !indexableRoutes.includes(normalizeRoute(r)));
if (missing.length || extra.length) {
  throw new Error(`تغطية الخريطة غير مطابقة: ناقص ${missing.join(", ")} | زائد ${extra.join(", ")}`);
}
```

**ملاحظات تنفيذية:**
- الصفحات القديمة القابلة للفهرسة تُفحَص في `publish-static.mjs` بنفس الطريقة (المصدر: المسارات التي ينسخها فعلاً، لا ملفات الجذر القديمة — لتجنّب صفحات متقادمة).
- هذا الفحص **يفشل البناء دائماً**، لا تحذيراً: تغطية ناقصة عيب حقيقي، لا سياسة.
- لا تُكرِّر استدعاء `renderPage` مرتين للصفحة نفسها إن كان ذلك مكلفاً — اجمع `seo` في الحلقة الحالية ثم افحص بعدها.

**معيار القبول:** أضف مؤقتاً مساراً وهمياً في اختبار محلي وأثبت أن البناء يفشل برسالة تسمّي المسار، ثم احذفه. أرفق الإثبات.

### P4 — 🟡 صفحة `/blog/http-protocols` لا تمرّ على أي حارس

هذه الصفحة مكتوبة يدوياً في الجذر وليست في مسارات React ولا في `website/legacy`، لذلك لا `prerender` ولا `publish-static` يفحصها. وهي **الصفحة الوحيدة** التي تحمل البراند في `<title>` ولم تُرصد (41 عنواناً فيه البراند، 40 مرصوداً فقط).

**المطلوب:** أضف قائمة صريحة `HAND_AUTHORED_INDEXABLE = ["/blog/http-protocols"]` تُفحَص بنفس القواعد، وأدرجها في فحص التغطية (P3). إن وُجدت صفحات يدوية أخرى، أدرجها كلها.

**معيار القبول:** ظهور الصفحة في التقرير (واحدة من 18/40 بحسب تصنيفها)، أو إثبات أنها `noindex` فتُستثنى صراحةً مع تعليق.
