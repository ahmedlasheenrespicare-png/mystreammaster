# Stream Master Pro — التصميم الجديد

أُعيد تصميم واجهة المتجر باستخدام ملفات الموقع المرجعي الذي حدده صاحب المشروع:
`ahmedlasheenrespicare-png/serverproject`، الإصدار `48c72d057df8e1917c9a18e4bfdd436adfd94d25`.

## ما تغير

- تصميم RTL بخلفية كريمية، نص داكن، ولمسات ليمونية وبنفسجية؛ نفس أقسام الرئيسية والحركات والصور والخطوط المحلية للموقع المرجعي.
- صفحات الرئيسية، المتجر، السيرفرات، القنوات، المدونة، الأسئلة الشائعة والسلة مبنية بمكونات React مشتركة ومولّدة مسبقاً إلى HTML.
- المقالات العربية القديمة، صفحات السياسات، البحث، حالة الخدمة، التوقعات وكأس العالم والبث المجاني احتفظت بروابطها ومحتواها وسكربتاتها، مع واجهة وألوان مشتركة جديدة.
- بقيت العروض السنوية المعروضة في المتجر: نوفا **25 دولار**، إيستار **35 دولار**، موكا **45 دولار**. لم تُستورد عروض وأسعار المرجع؛ تحويل العملات تقديري بالأسعار الثابتة الموجودة في الإعدادات، وليس سعراً مصرفياً لحظياً.
- بقي رقم واتساب الموقع `201098950879`. السلة تُحفظ محلياً وتستورد العناصر السنوية من السلة القديمة، ثم تعيد حساب أسعارها من الكتالوج.
- لم تُعدّل ملفات PHP أو لوحة الإدارة أو قائمة النطاقات المسموح بها.
- الهيدر منظم في خمس قوائم منسدلة — الرئيسية (كل أقسامها)، السيرفرات والباقات، القنوات والبث، المقالات، المساعدة — ويضم كل صفحات الموقع. الهيدر الجديد وهيدر الصفحات القديمة يُبنيان من `website/src/navigation.mjs`؛ أضف أي صفحة جديدة هناك فقط.
- دُمجت قنوات تصنيف «قنوات MBC» (13 قناة: MBC 1، MBC Masr 1/2، MBC Masr Drama، MBC Drama، MBC 4، MBC 5، MBC Bollywood، MBC Persia، العربية، الحدث، العربية أسواق، MBC Loud FM) من `channels.json` في الموقع المرجعي إلى أعلى `channels.json`، وصُححت روابط ثلاث قنوات في `FEATURED_CHANNELS` لتطابق المرجع.

## التشغيل

يتطلب Node.js 22:

```sh
npm run setup       # تثبيت الاعتمادات من website/package-lock.json
npm run build       # بناء React + SSR، ثم تحديث ملفات النشر في جذر المستودع
npm run preview     # معاينة جميع الصفحات على 0.0.0.0:3000
```

`npm run dev` يشغّل Vite لتطوير صفحات React فقط. لمعاينة الصفحات القديمة وملفات القنوات معاً، استخدم البناء ثم `npm run preview`.

## أماكن التعديل

| المسار | الغرض |
| --- | --- |
| `website/src/components/` | مكونات التصميم المرجعي |

| `website/src/content/` | المقالات الجديدة وفهرس المقالات القديمة |
| `website/public/` | الصور والخطوط وطبقة تصميم الصفحات القديمة |

**لا تعدّل HTML المولّد في الجذر مباشرة**؛ عدّل مصدره ثم أعد البناء. الملفات المولّدة تحت `_assets/redesign/` وملفات HTML محفوظة في Git عمداً، لأن الاستضافة الحالية تنشر موقعاً ثابتاً من جذر المستودع.

## التحقق

```sh
npm run typecheck
npm test            # اختبارات قارئ القنوات والوسيط
npm run test:ui     # اختبارات Chromium: الجوال، السلة، التنقل، النوافذ والروابط القديمة
```

اختبارات المتصفح تمنع الاتصالات الخارجية عمداً. لا تثبت هذه الاختبارات صلاحية بث القنوات أو وصول رسائل واتساب. معاينة Node ثابتة ولا تشغّل PHP؛ يلزم فحص البث وواجهات الإدارة على استضافة تدعم PHP. لم يُنشر Cloudflare Worker جديد؛ مصدره المرفق من المرجع للاختبارات فقط.

## النشر

سير عمل Hostinger الحالي أصبح يبني الموقع قبل رفعه عند التحديث على `main`، ويستثني `website/` والاعتمادات من الرفع. هناك أيضاً فحوص البناء والواجهة لطلبات الدمج وفروع Arena. هذه التعديلات لا تنشر الموقع أو تدمج الفرع تلقائياً.

ملاحظة: نموذج تحديثات العروض يفتح طلباً عبر واتساب؛ لا يدّعي إرسال بريد إلكتروني دون وجود خدمة بريد خلفية. قائمة البث الإضافية `kora-live.m3u8` تبدأ فارغة عمداً، ولم تُنسخ بيانات بث خاصة من المرجع. البث المجاني الحالي وقائمة قنواته الأصلية باقيان.

## صفحة مواعيد المباريات — `/matches/`

- مصدر الواجهة: `website/src/pages/MatchesPage.tsx`، والتصميم: `website/src/pages/matches.css`، والوسيط الخلفي: `scoreboard.php`.
- شريط الأدوات (حالة التحديث التلقائي، المنطقة الزمنية، البطولة، البحث عن فريق، زر تحديث فوري) لاصق أسفل الهيدر، وجدول الأيام والمباريات يظهر مباشرةً تحته في أعلى الصفحة. التحديث التلقائي دائم التشغيل بلا مفتاح إيقاف في الواجهة.
- التاريخ في المتصفح يُحسب حسب المنطقة المختارة؛ يعرض الشريط ١٥ يومًا (٧ سابقة + اليوم + ٧ قادمة) ويتجدد عند منتصف الليل. لا تُثبت التواريخ أثناء البناء.
- المواعيد بتوقيت مكة ومصر وUTC ظاهرة في كل بطاقة، مع اختيار بقية مناطق IANA العالمية وحفظ الاختيار محليًا. تحويل `Intl` يراعي التوقيت الصيفي في مصر، وتُعرض تواريخ كل منطقة إذا اختلف اليوم.
- المتصفح يطلب `/scoreboard.php?league={league}&dates={dates}` من نفس نطاق الموقع بدل الاتصال المباشر بـESPN، ويتولى `scoreboard.php` التحقق من القائمة البيضاء للبطولات والتواريخ ثم جلب `https://site.api.espn.com/apis/site/v2/sports/soccer/{league}/scoreboard` مع تخزين مؤقت على الخادم (`CACHE_TTL = 45s`) ونسخة احتياطية قصيرة (`STALE_TTL = 600s`) عند تعطل المصدر مؤقتًا. البطولات المغطاة مذكورة صراحة في `website/src/lib/matches.mjs` و`scoreboard.php`؛ ليست تغطية لكل مباريات العالم. أسماء الفرق تأتي كما يرسلها المصدر، وقد تكون بالإنجليزية.
- الصفحة تُحمّل اليوم المختار مع اليوم السابق والتالي بتوقيت UTC ثم تُصفي حسب المنطقة الزمنية، لتجنب فقد مباريات قرب منتصف الليل. التحديث التلقائي كل ٦٠ ثانية دائم التشغيل أثناء ظهور الصفحة واتصالها بالإنترنت (لا مفتاح إيقاف في الواجهة)، مع زر تحديث فوري. يتوقف الطلب مؤقتًا فقط حين يكون التاب مخفيًا أو الجهاز غير متصل، ثم يستأنف تلقائيًا. لا تُحسب النتائج أو دقائق اللعب تخمينيًا.
- فشل المصدر أو بطولة معينة له تنبيه منفصل عن اليوم الخالي من المباريات، ويُعرض معه رمز تشخيص واضح (مثل `UPSTREAM_HTTP_503`، `UPSTREAM_TIMEOUT`، `DNS_LOOKUP_FAILED`، `PHP_UNAVAILABLE`، `PHP_PREVIEW_UNAVAILABLE`، `REQUEST_TIMEOUT`) لتحديد سبب الفشل بدقة. تُحفظ آخر بيانات اليوم نفسه أثناء فشل التحديث، وتُوسم بأنها قديمة؛ لا تُحفظ النتائج في Service Worker.
- **مصدر الدوري السعودي والدوري المصري:** لا توفّرهما ESPN، لذلك يجلبهما `/scoreboard.php` من TheSportsDB (`www.thesportsdb.com`، المعرّفات `4668` و`4829`) ويطبّع استجابتهما إلى نفس بنية ESPN. باقي البطولات من ESPN.
- **متطلبات الإنتاج:** يتطلب `/scoreboard.php` استضافة تشغّل PHP مع تفعيل `cURL` (أو `allow_url_fopen`) وإمكانية وصول الخادم خارجيًا إلى `site.api.espn.com` و`www.thesportsdb.com`. في المعاينة الثابتة (`npm run preview`) لا يعمل PHP ويعود الرمز التشخيصي `PHP_PREVIEW_UNAVAILABLE`. لا توجد بيانات مباريات وهمية منشورة ولا مفتاح API داخل الملفات.
- **حدود التحقق:** الاتصالات في اختبارات المتصفح محاكاة ببيانات اختبار فقط؛ بيئة العمل لا تشغّل PHP ولا تسمح باتصال ESPN، لذا لا تثبت الاختبارات صلاحية المصدر الفعلي أو عمل PHP على الاستضافة. يلزم فحص `/matches/` و`/scoreboard.php` على الاستضافة الفعلية بعد النشر.
- `npm test` يتحقق من قارئ النتائج، حدود الأيام، التوقيت الصيفي، رموز التشخيص وعقد `scoreboard.php`. `website/tests/matches.spec.ts` يتحقق من التحديث التلقائي الدائم (وبقاء الواجهة بلا مفتاح إيقاف)، التصفية والتواريخ والمناطق الزمنية، رموز التشخيص عند الأعطال، الكاش الاحتياطي والجوال والتنقل.

- Only first-party HTTPS destination pages belong in this data file. Do not add

- A network homepage is labelled as a network destination; inclusion is not a

- Current links carry no affiliate parameters and no click tracking. Add affiliate

  and any privacy changes required by the actual tracking implementation.

## مشغّل اشتراكك الشخصي — تطوير القسم (`#xtream`)

منطق القسم انتقل بالكامل إلى `website/src/lib/xtream.mjs` (دوال خالصة، بلا DOM
وبلا React) وأنواعه في `website/src/lib/xtream.d.mts`، وبقي
`website/src/components/XtreamPlayer.tsx` للواجهة فقط. الهدف: منطق واحد مُختبَر
يُعاد استخدامه، لا نسخة مكرّرة داخل المكوّن.

### ما أُضيف

- **تعدد الحسابات:** قائمة حسابات محفوظة (`smp-xtream-accounts`) مع شرائح للتبديل
  الفوري وحذف حساب. الجلسة القديمة (`smp-xtream-account`) تُهاجَر تلقائياً إلى القائمة،
  وتبقى مكتوبة للتوافق مع الإصدار السابق.
- **مفضلة وسجل مشاهدة لكل حساب على حدة** (`smp-xtream-favorites`، `smp-xtream-recents`)
  بمفتاح ملف (`profileKeyFor`) لأن أرقام القنوات تختلف من مزوّد لآخر — لا تختلط قوائم
  حسابين، وملف M3U له ملف مستقل.
- **بحث عربي موحّد** (`normalizeArabic` + `matchesQuery`): الهمزات والتاء المربوطة
  والياء والتشكيل والأرقام العربية، وكل الكلمات بلا ترتيب، ويعمل على **كل** القنوات في
  كل التصنيفات لا داخل التصنيف المختار فقط.
- **قائمة قنوات افتراضية (Virtual):** أُزيل سقف «أول 300 قناة» (`list.slice(0, 300)`)
  واستُبدل بحساب نطاق الرسم (`windowRange`) وصف بارتفاع ثابت، فأي عدد قنوات يُعرض بسلاسة
  مع بقاء عدد عناصر DOM صغيراً.
- **أدوات المشغل:** اختيار الجودة من مستويات hls.js، صورة داخل صورة، ملء الشاشة،
  وعدّاد الأيام المتبقية في الاشتراك (`daysUntil`) مع تنبيه عند 7 أيام أو أقل.
- **تقرير تشخيص قابل للمشاركة:** `createShareToken` يبني رمزاً قصيراً (`SMP1.…`)
  بلا كلمة سر واسم مستخدم مقنّع (`maskUsername`)، مع نسخ الرمز أو إرساله للدعم عبر
  واتساب (`WHATSAPP_NUMBER` في `src/config.ts`).
- سحب ملف M3U وإفلاته، وإصلاح ترتيب رسائل الفشل: كل المحاولات المنتهية بمهلة تُوصف
  بأنها «لا استجابة» بدل نسبتها إلى حجب CORS.

### إصلاحان خارج نطاق القسم

- **لا إرسال أصلي قبل التحميل:** كان النموذج `<form>` مع `onSubmit` — وقبل انتهاء
  hydration (الصفحة مرسومة مسبقاً) يؤدي أي إرسال أصلي إلى إعادة تحميل الصفحة ووضع
  اسم المستخدم وكلمة السر في الرابط وسجل الخادم. صار حاوية `role="form"` مع زر
  `type="button"` ومعالجة Enter يدوياً، فالنقر قبل التحميل بلا أثر ولا سرّ في الرابط.
- **روابط الأقسام تصل فوراً:** `useHashScroll` في `HomePage.tsx` يعيد التمرير بعد أول
  إطار وبعد اكتمال التحميل، وبسلوك `instant` ليتجاوز `scroll-behavior: smooth`،
  وصفحات React صارت تحترم `prefers-reduced-motion` في التمرير كما تفعل صفحات المتجر
  القديمة. (كان الانتقال إلى `/#faq` من صفحة أخرى يفشل أحياناً.)

### التحقق

```sh
npm test           # 55 فحصاً — منها 29 لمشغّل الاشتراك في scripts/test-xtream.mjs
npm run typecheck
npm run test:ui -- tests/xtream-player.spec.ts    # 6 اختبارات للقسم
```

`website/tests/xtream-player.spec.ts` يعمل بمحاكاة كاملة للسيرفر (400 قناة) ويقطع كل
اتصال خارجي، ويستعمل `serviceWorkers: 'block'` لأن عامل الخدمة كان يعترض طلبات
المحاكاة خارج نطاق `page.route`، وينتظر اكتمال hydration قبل التفاعل. الاختبارات
تتحقق من الواجهة والمنطق المحلي فقط، **ولا تثبت صلاحية بث أي مزوّد** ولا عمل الوسيط.

### ملاحظات تبقى قائمة

- مسار الملف M3U لا يزال يستعمل `PROXY_BASE` في `m3uCandidates` كمرشّح أخير. تمرير بث
  المشترك عبر سيرفر يخصّنا هو النقطة الأضعف قانونياً في هذا القسم، وإزالته تحتاج قراراً
  منفصلاً لأنها قد تُفقد بعض المشتركين التشغيل.
- مسارات غير منفَّذة بعد من خطة التطوير: الأفلام والمسلسلات (`get_vod_streams`،
  `get_series`)، دليل البرامج (EPG)، «افحص حالة اشتراكك» كصفحة تسويقية، النسخة البيضاء،
  والتضمين للشركاء.
