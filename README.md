# Stream Master Pro — التصميم الجديد

أُعيد تصميم واجهة المتجر باستخدام ملفات الموقع المرجعي الذي حدده صاحب المشروع:
`ahmedlasheenrespicare-png/serverproject`، الإصدار `48c72d057df8e1917c9a18e4bfdd436adfd94d25`.

## ما تغير

- تصميم RTL بخلفية كريمية، نص داكن، ولمسات ليمونية وبنفسجية؛ نفس أقسام الرئيسية والحركات والصور والخطوط المحلية للموقع المرجعي.
- صفحات الرئيسية، المتجر، السيرفرات، القنوات، المدونة، الأسئلة الشائعة والسلة مبنية بمكونات React مشتركة ومولّدة مسبقاً إلى HTML.
- المقالات العربية القديمة، صفحات السياسات، البحث، حالة الخدمة، التوقعات وكأس العالم احتفظت بروابطها ومحتواها وسكربتاتها، مع واجهة وألوان مشتركة جديدة. أما `/live-free.html` فتحوّلت إلى صفحة «مشغّل الويب الذكي»: مشغّل اشتراك المشترك الشخصي + جولة تفاعلية وبطاقات مميزات، بلا أي رابط بث مدمج.
- بقيت العروض السنوية المعروضة في المتجر: نوفا **25 دولار**، إيستار **35 دولار**، موكا **45 دولار**. لم تُستورد عروض وأسعار المرجع؛ تحويل العملات تقديري بالأسعار الثابتة الموجودة في الإعدادات، وليس سعراً مصرفياً لحظياً.
- بقي رقم واتساب الموقع `201098950879`. السلة تُحفظ محلياً وتستورد العناصر السنوية من السلة القديمة، ثم تعيد حساب أسعارها من الكتالوج.
- لم تُعدّل ملفات PHP أو لوحة الإدارة أو قائمة النطاقات المسموح بها.
- الهيدر منظم في خمس قوائم منسدلة — الرئيسية (كل أقسامها)، السيرفرات والباقات، القنوات والبث، المقالات، المساعدة — ويضم كل صفحات الموقع. الهيدر الجديد وهيدر الصفحات القديمة يُبنيان من `website/src/navigation.mjs`؛ أضف أي صفحة جديدة هناك فقط.
- `channels.json` (الجذر) صار فهرساً وصفياً فقط: 240 قناة باسمها وشعارها وتصنيفها بلا أي حقل رابط. حُذفت روابط البث من الملف ومن `FEATURED_CHANNELS` في `website/src/data.ts`، وحُذف `channels.backup.json` نهائياً. الفهرس يُعرض في `/channels/` بالبحث والتصنيفات، والقوائم القابلة للتشغيل تُجلب من مزوّد المشترك داخل مشغّله في متصفحه فقط (`/#xtream`).

## التشغيل

يتطلب Node.js 22:

```sh
npm run setup       # تثبيت الاعتمادات من website/package-lock.json
npm run build       # بناء React + SSR، ثم تحديث ملفات النشر في جذر المستودع
npm run preview     # معاينة جميع الصفحات على 0.0.0.0:3000
```

`npm run dev` يشغّل Vite لتطوير صفحات React فقط. لمعاينة الصفحات القديمة وملفات القنوات معاً، استخدم البناء ثم `npm run preview`.

### جدول الترتيب وإدخال بطولة جديدة

قسم «جدول الترتيب» في صفحات البطولات مبنيّ على قاعدتين ثابتتين:

1. **الجدول كامل في HTML وقت البناء** من لقطة المصدر (`src/content/standings-snapshot.json`)،
   فلا يعتمد ظهوره على JavaScript؛ والتحديث التلقائي (عند الفتح وكل دقيقة) طبقة فوقه
   عبر `standings.php` بمعرّف البطولة، مع «آخر قراءة مؤكدة» ووسم «بيانات قديمة» عند التعذّر.
   اللقطة تُجلب من المصدر وتُحكَّم آلياً: `.github/workflows/standings-snapshot.yml` يشغّل
   `scripts/fetch-standings-snapshot.mjs` (جلب خام → حكم بنفس قواعد الوسيط → تحقق الواجهة →
   كتابة اللقطة وتقرير المسبار `website/docs/standings-probe-report.json`)، ولا يكتب على `main` أبداً.
2. **لا تُضاف بطولة بترتيب إلا بمسبار موثّق**: شغّل
   `node scripts/probe-standings.mjs <league>` محلياً، أو اطلب جلبها من التشغيل الآلي،
   فأي بطولة ينجح فحصها فقط تُضاف إلى قائمة `standings.php` المسموحة **و** إلى
   `STANDINGS_LEAGUES` في `src/lib/standings.mjs` **و** إلى لقطة الترتيب. وما يفشل
   يبقى بنص صريح «غير متاح من مصدر موثّق» ولا يُستكمل من موقع آخر ولا يُخمَّن —
   ومثاله الموثّق: الدوري المصري `egy.1` رفض ESPN طلبه (HTTP 400) في مسبار
   2026-10-16 فبقي «غير متاح»، حتى أثبته مسبار ثانٍ لدى Highlightly في
   2026-10-17 — البوابة تُفتح بالدليل لا بالاستعجال.

   في `standings.php` قائمتان: `SM_ST_LEAGUES` (بطولات لقطة التوثيق الثلاث، وهي عين
   ما يبني عليه اختبار التشغيل القائم عيّناته) و`SM_ST_LEAGUES_PROVEN` (بطولات أُضيفت
   بعد مسبار مثبت)، ويخدم الوسيط مجموعهما بتحقق واحد بلا استثناء. وترتيب صفحات
   البطولات المنشورة: أبطال أوروبا ← الإنجليزي ← الفرنسي ← الإسباني ← الألماني ←
   الإيطالي ← السعودي ← المصري.

ترتيب البطولات في القوائم وصفحة المواعيد مصدره واحد: `LEAGUE_PAGE_ORDER` في
`src/content/competitions.ts`، ويحرسه `scripts/test-league-standings.mjs`
(يطابق المصدرين ويرفض بطولة تُنشر بلا رابط أو بترتيب مختلف).

### بطولات جدول المواعيد — الإضافة والإثبات

قائمة بطولات جدول المواعيد (`/matches/`) مصدرها `LEAGUES` في
`website/src/lib/matches.mjs`، ويجب أن تطابقها `ALLOWED_LEAGUES` في
`scoreboard.php` **عنصراً بعنصر وبنفس الترتيب** — يحرس المطابقة اختبار
`scripts/test-matches.mjs`. البطولة تظهر من القائمة ذاتها في ثلاثة مواضع
بلا تعديل ثانٍ: خيارات التصفية، وأقسام الجدول، وطلبات التحديث كل دقيقة.

أُضيفت ثلاث بطولات قارية إلى الجدول (دون صفحة هبوط مخصصة):

| المعرّف | الاسم في الجدول |
| --- | --- |
| `caf.champions` | دوري أبطال أفريقيا |
| `caf.confed` | كأس الكونفدرالية الأفريقية |
| `afc.champions` | دوري أبطال آسيا للنخبة |

حدود هذه الإضافة، صراحةً:

- **جدول وفلتر فقط** — لا صفحة `/matches/<slug>/`، ولا جدول ترتيب، ولا إدراج
  في أرشيف المباريات (`ARCHIVE_LEAGUES` يبقى اثنتي عشرة بطولة وله بوابته
  الخاصة في `website/docs/fixtures-archive.md`).
- **التسجيل في القائمة ليس إثبات تغطية.** الإثبات خطوة منفصلة بمسبار محلي:

  ```sh
  node website/scripts/probe-matches-leagues.mjs caf.champions caf.confed afc.champions
  node website/scripts/probe-matches-leagues.mjs   # كل البطولات
  ```

  المسبار لا يعدّل أي ملف: يسأل المصدر في نافذة ±7 أيام ويحكم بالدالة ذاتها
  التي تعرض بها الصفحة الجدول (`parseScoreboard`)، ويرفض استجابة تعيد
  معرّف بطولة غير المطلوب (`SOURCE_ID_MISMATCH`)، ويقبل «لا مباريات في
  النافذة» نتيجةً صريحة لا فشلاً — فأسبوع بلا جولة وارد في بطولة قائمة.
- **إن لم يخدم المصدر معرّفاً**، تظهر البطولة في الصفحة برسالة «تعذر تحديث…»
  ورمز تشخيص واضح، لا بقسم فارغ صامت. وفي هذه الحالة يُصحَّح المعرّف في
  `LEAGUES` و`ALLOWED_LEAGUES` معاً (أو يُحذف) بعد المسبار — لا يُترك معرّف
  فاشل في القائمة يستهلك طلباً كل دقيقة ويشوّش التشخيص.

### بوابة الدوري المصري (`egy.1`) — أدلة المسبار الموثّقة (2026-10-17)

صفحة الدوري المصري (`/matches/الدوري-المصري/`) منشورة بمبارياتها حيّة
(`leagueId: "egy.1"` لدى `scoreboard.php` عبر TheSportsDB `eventsround`) وجدول ترتيبها
من **Highlightly** — المصدر المجاني الوحيد الذي اجتاز البوابة الخمسة
(خطة مجانية دائمة · تغطية مصر · نقطة جداول · موسم حالي · شروط استخدام
تصرّح بالعرض). سُجِّلت كل محاولة في `website/docs/standings-probe-report.json`:

| المرشح | النتيجة | السبب الموثّق |
|---|---|---|
| **Highlightly** | ✅ ناجح | leagueId=199067، موسم 2026، 20 فريقاً بمراكز فريدة 1..20 — جدول حيّ (6 جولات) ورسالة الخطة الصريحة «All data available with current plan» |
| ESPN (`egy.1`) | ❌ رفض | HTTP 400 صريح: «Unable to retrieve any standings information for egy.1» — المصدر ينفي امتلاكه جداول للدوري أصلاً |
| API-Football (api-sports.io) | ❌ حجب الموسم | الخطة المجانية صحيحة ($0، 100 طلب/يوم، Standings مشمولة) لكنها تحجب المواسم الحالية صراحة: «Free plans do not have access to this season, try from 2022 to 2024» |
| TheSportsDB (مفتاح 123 المجاني) | ❌ اقتطاع | يرسل 200 لكن 5 صفوف فقط من 20 — أُثبت أن الاقتطاع قيد مفتاح: الدوري الإنجليزي (20 فريقاً) عاد هو الآخر بـ5 صفوف |
| football-data.org | ❌ خارج التغطية | مصر ليست ضمن الخطة المجانية |
| azharimm/football-standings-api | ❌ خارج التغطية | قائمة البطولات ثابتة في الكود (20 بطولة) بلا مصر، وسيطه مبني على ESPN نفسه |
| worldcup26.ir | ❌ خارج التغطية | 35 مسابقة مغطاة بإعلان «إنجلترا وإسبانيا» فقط، ومعرّفاته كلها بصيغة ESPN |
| openfootball/football.json | ❌ مستبعَد | نتائج خام CC0 لا ترتيب جاهز — والحساب المحلي ممنوع بعقد الترتيب |
| egyptianproleague.com | ❌ بلا API عامة | `/api/standings` يحوّل إلى الصفحة الرئيسية — الموقع الرسمي لا يعرض JSON |
| statorium.com | ❌ مدفوع | نموذج «اطلب عرض سعر» مؤسسي |
| live-score-api.com | ❌ تجربة فقط | يغطي مصر (ID 36) لكن «المجانية» تجربة 14 يوماً تنتهي لاشتراك مدفوع |
| TheStatsAPI · Sportmonks · 5DollarFootballAPI | ❌ مدفوع/مقيد | $50/شهر أدنى حد · المجانية لدوريتين أوروبيتين · المجانية للخمسة الكبار فقط |

القاعدة الحاكمة (بند ⑥): ما لا يثبت مصدره يبقى «غير متاح» بصراحة — لا
استكمال من موقع آخر ولا تخمين. إدخال البطولة إلى `standings.php` و
`STANDINGS_LEAGUES` يتم فقط بعد مسبار ناجح يطبع: معرّف المصدر + عدد
فرق مطابق (20) + مراكز فريدة 1..N، ثم جلب اللقطة عبر جسر الجلب لا يدوياً.
مفتاح Highlightly يُقرأ من بيئة التشغيل (`SM_HIGHLIGHTLY_KEY` على الخادم
للوسيط، و`HIGHLIGHTLY_API_KEY` سرّاً في Actions لجسر الجلب) ولا يدخل
المستودع ولا المحادثة أبداً.

الناقل الرسمي للدوري المصري مؤجَّل أيضاً: لم يُوثَّق بيان أولي رسمي (من
الرابطة أو الجهة الناقلة) لحقوق موسم 2026-27، فظهر القسم بنص الحالة
بصراحة بدل اختراع جهة — وتُوثَّق الرابطة نظام الموسم (20 نادياً، مرحلة
أولى من دور واحد، ثم مجموعة لقب 1–6 ومجموعة بقاء 7–20 يهبط منها 4)
من بيان القرعة الرسمي على egyptianproleague.com.

`scripts/test-proxy-php.mjs` يفحص **مصدر** `proxy.php` (بصمة المشغّل، متابعة تحويل
`302`، الحفاظ على `Range` و`206`، معاملات جلسة قائمة HLS، كوكيز القفزات، وحدود
SSRF/CORS)، و`scripts/test-embed-php.mjs` يفحص وسيط التضمين `/embed.php` بالطريقة
نفسها، لأن بيئة الاختبار لا تشغّل PHP — نفس الأسلوب المتبع مع `scoreboard.php`.
فهو يضمن بقاء العقد قائماً، ولا يغني عن فحص البث على الاستضافة الفعلية.

## النشر

سير عمل Hostinger الحالي أصبح يبني الموقع قبل رفعه عند التحديث على `main`، ويستثني `website/` والاعتمادات من الرفع. هناك أيضاً فحوص البناء والواجهة لطلبات الدمج وفروع Arena. هذه التعديلات لا تنشر الموقع أو تدمج الفرع تلقائياً.

**لا رجوع إلى نسخة أقدم:** كل تشغيل لـ`Deploy to Hostinger` ينشر **أحدث** `main`
(`ref: main`) لا الالتزام الذي أطلقه، وعمليات النشر متسلسلة (`concurrency`) فلا
تتداخل ولا يُقطع رفع جارٍ. السبب: في 2026-10-14 وصل حدث الدفع لدمج #36 مرتين،
فرفع التشغيل المكرّر بناءً أقدم فوق إصلاح #35 بعد نشره. ملخّص كل تشغيل يذكر الالتزام
المنشور فعلاً، ولإعادة نشر `main` يدوياً: Actions ← Deploy to Hostinger ← Run workflow.
البناء حتمي، فبصمة sha256 لأي ملف مبني محلياً تطابق بصمته في ملف حالة الرفع
`.ftp-deploy-sync-state.json` على الخادم — هكذا يُعرف أي نسخة منشورة.

ملاحظة: نموذج تحديثات العروض يفتح طلباً عبر واتساب؛ لا يدّعي إرسال بريد إلكتروني دون وجود خدمة بريد خلفية. صفحة `/live-free.html` لم تعد تعرض أي قناة ولا مشغّلاً عاماً: كل روابط البث المدمجة (~300 رابط) ومضيفاتها والقائمة المدمجة حُذفت نهائياً، وقسم المشغّل العام `LivePlayer` أُزيل من الواجهة. الصفحة الآن تعريفية بمشغّل اشتراك المشترك (`/#xtream`) مع جولة تفاعلية وبطاقات مميزات، وقائمة `kora-live.m3u8` تبقى فارغة عمداً بلا أي بيانات بث.

## صفحة مواعيد المباريات — `/matches/`

- مصدر الواجهة: `website/src/pages/MatchesPage.tsx`، والتصميم: `website/src/pages/matches.css`، والوسيط الخلفي: `scoreboard.php`.
- شريط الأدوات (حالة التحديث التلقائي، المنطقة الزمنية، البطولة، البحث عن فريق، زر تحديث فوري) لاصق أسفل الهيدر، وجدول الأيام والمباريات يظهر مباشرةً تحته في أعلى الصفحة. التحديث التلقائي دائم التشغيل بلا مفتاح إيقاف في الواجهة.
- التاريخ في المتصفح يُحسب حسب المنطقة المختارة؛ يعرض الشريط ١٥ يومًا (٧ سابقة + اليوم + ٧ قادمة) ويتجدد عند منتصف الليل. لا تُثبت التواريخ أثناء البناء.
- المواعيد بتوقيت مكة ومصر وUTC ظاهرة في كل بطاقة، مع اختيار بقية مناطق IANA العالمية وحفظ الاختيار محليًا. تحويل `Intl` يراعي التوقيت الصيفي في مصر، وتُعرض تواريخ كل منطقة إذا اختلف اليوم.
- المتصفح يطلب `/scoreboard.php?league={league}&dates={dates}` من نفس نطاق الموقع بدل الاتصال المباشر بـESPN، ويتولى `scoreboard.php` التحقق من القائمة البيضاء للبطولات والتواريخ ثم جلب `https://site.api.espn.com/apis/site/v2/sports/soccer/{league}/scoreboard` مع تخزين مؤقت على الخادم (`CACHE_TTL = 45s`) ونسخة احتياطية قصيرة (`STALE_TTL = 600s`) عند تعطل المصدر مؤقتًا. البطولات المغطاة مذكورة صراحة في `website/src/lib/matches.mjs` و`scoreboard.php`؛ ليست تغطية لكل مباريات العالم. أسماء الفرق تأتي كما يرسلها المصدر، وقد تكون بالإنجليزية.
- الصفحة تُحمّل اليوم المختار مع اليوم السابق والتالي بتوقيت UTC ثم تُصفي حسب المنطقة الزمنية، لتجنب فقد مباريات قرب منتصف الليل. التحديث التلقائي كل ٦٠ ثانية دائم التشغيل أثناء ظهور الصفحة واتصالها بالإنترنت (لا مفتاح إيقاف في الواجهة)، مع زر تحديث فوري. يتوقف الطلب مؤقتًا فقط حين يكون التاب مخفيًا أو الجهاز غير متصل، ثم يستأنف تلقائيًا. لا تُحسب النتائج أو دقائق اللعب تخمينيًا.
- فشل المصدر أو بطولة معينة له تنبيه منفصل عن اليوم الخالي من المباريات، ويُعرض معه رمز تشخيص واضح (مثل `UPSTREAM_HTTP_503`، `UPSTREAM_TIMEOUT`، `DNS_LOOKUP_FAILED`، `PHP_UNAVAILABLE`، `PHP_PREVIEW_UNAVAILABLE`، `REQUEST_TIMEOUT`) لتحديد سبب الفشل بدقة. تُحفظ آخر بيانات اليوم نفسه أثناء فشل التحديث، وتُوسم بأنها قديمة؛ لا تُحفظ النتائج في Service Worker.
- **مصدر الدوري السعودي والدوري المصري (`sau.1` و`egy.1`):** لا توفّرهما ESPN، لذلك يجلبهما `/scoreboard.php` من TheSportsDB (`www.thesportsdb.com`، المعرّفان `4668` و`4829`) عبر نقطة `eventsround.php` التي تُرجع الجولة كاملة، ويطبّع استجابتهما إلى نفس بنية ESPN. مفتاح TheSportsDB المجاني `123` هو الافتراضي (وهو المفتاح العام المعلن)، ويمكن تغييره بمتغير البيئة `SM_SPORTSDB_KEY` على الخادم. لماذا لا `eventsday`: مفتاح `3` أُوقف، وينتج عنه أيضاً 3 مباريات لليوم فقط؛ ولا `eventsseason`: ينتج 15 حدثاً فقط للموسم.
  - **التخزين:** كل جولة تُحفظ في ملف JSON واحد داخل `SM_DATA_DIR/smp_sportsdb_rounds/` (أو مجلد النظام المؤقت إن لم يُضبط المتغير؛ يُفضّل ضبطه خارج `public_html`). اليوم المطلوب يُحدَّد بالبحث الثنائي على الجولات `1..40`.
  - **مواعيد التحديث:** الجولة المنتهية بالكامل تُجمَّد ولا تُطلب بعد ذلك؛ الجولة الجارية تُحدَّث كل 60 ثانية، والمجدولة بالكامل كل 900 ثانية، والفارغة (ما بعد نهاية الموسم) كل 3600 ثانية.
  - **الحماية من الاقتطاع:** أي جولة تُرجع 15 حدثاً أو أكثر تُرفض برمز `UPSTREAM_TRUNCATED`.
  - **عند تعطل المصدر:** تُعاد آخر نسخة مخزنة للجولة مع `STALE` ورمز التشخيص. لا تُكتب هذه الاستجابة كنسخة طازجة.
- **متطلبات الإنتاج:** يتطلب `/scoreboard.php` استضافة تشغّل PHP مع تفعيل `cURL` (أو `allow_url_fopen`) وإمكانية وصول الخادم خارجيًا إلى `site.api.espn.com` و`www.thesportsdb.com`. في المعاينة الثابتة (`npm run preview`) لا يعمل PHP ويعود الرمز التشخيصي `PHP_PREVIEW_UNAVAILABLE`. لا توجد بيانات مباريات وهمية منشورة ولا مفتاح API داخل الملفات.
- **حدود التحقق:** الاتصالات في اختبارات المتصفح محاكاة ببيانات اختبار فقط؛ بيئة العمل لا تشغّل PHP ولا تسمح باتصال ESPN، لذا لا تثبت الاختبارات صلاحية المصدر الفعلي أو عمل PHP على الاستضافة. يلزم فحص `/matches/` و`/scoreboard.php` على الاستضافة الفعلية بعد النشر.
- `npm test` يتحقق من قارئ النتائج، حدود الأيام، التوقيت الصيفي، رموز التشخيص وعقد `scoreboard.php`. `website/tests/matches.spec.ts` يتحقق من التحديث التلقائي الدائم (وبقاء الواجهة بلا مفتاح إيقاف)، التصفية والتواريخ والمناطق الزمنية، رموز التشخيص عند الأعطال، الكاش الاحتياطي والجوال والتنقل.

## زر المشاهدة الذكي في صفحة المواجهة

- الزر الرئيسي `#primary-watch` يقرأ إعداده من الوسم نفسه:
  - `data-watch-url` رابط البث الخارجي (يُترك فارغًا لتعطيله).
  - `data-watch-enabled="true|false"` مفتاح التفعيل؛ `false` يجعل الزر داخليًا دائمًا.
  - `data-full-time-minutes` النافذة التقديرية الكاملة (افتراضيًا 150 دقيقة؛ ارفعها لمباريات الوقت الإضافي والترجيح).
  - `href` الافتراضي هو صفحة المتابعة الداخلية، فيعمل الزر داخليًا حتى بدون JavaScript.
- ترتيب القرار (`resolveMode`): تعطيل الرابط ← صفحة المتابعة · حالة المصدر «انتهت» أو «تغيّر موعد اللقاء» ← صفحة المتابعة · تجاوز `data-full-time-minutes` من وقت الانطلاق ← صفحة المتابعة · غير ذلك (قبل الانطلاق أو خلال اللقاء) ← رابط البث المُفعَّل في تبويب جديد.
- لوحة النتيجة تُبلّغ الحالة عبر `window.__smFixtureWatch(state)` عند كل تحديث كل ٦٠ ثانية، ويُعاد تقييم القرار محليًا كل ٣٠ ثانية؛ فيتحول الزر تلقائيًا من رابط البث إلى صفحة المتابعة بعد صافرة النهاية بلا إعادة تحميل.
- النص والملاحظة يتغيران مع الحالة: «مشاهدة المباراة الآن» + تنبيه الرابط الخارجي، مقابل «صفحة المتابعة» + تنبيه أن الصفحة داخلية ولا تعرض أي بث.
- `website/tests/fixture-watch-state.spec.ts` يتحقق من الحالات السبع: قبل الانطلاق، خلال اللقاء، بعد الصافرة، التحول اللحظي بين لحظتين، تغليب «انتهت» من المصدر، تعطيل الرابط، والعمل بدون JavaScript.

## صفحة مشغّل البث الخاص — `/player.html` + وسيط التضمين `/embed.php`

- **الغرض:** صفحة مستقلة (بلا هيدر/فوتر ولا `storefront.css`) تعرض مشغّل البث الخاص
  داخل إطار يملأ الشاشة. المصدر المنسوخ: `website/legacy/player.html`، والمنشور
  المولَّد: `player.html` (يُنشر عبر `npm run build`، ولا يُحرَّر يدويًا).
- **بلا رابط نفق في الصفحة:** إطار المشغّل يشير إلى `/player/five_channels_full.html`
  على **نفس النطاق**، والقاعدة في `.htaccess` تمرّره إلى `embed.php?u=player&p=/…`،
  والوسيط يجلب المحتوى من الأصل الحقيقي. لذلك لا يظهر رابط النفق المؤقت في مصدر
  الصفحة ولا في `frame-src`، ولا حاجة لتعديل CSP مع كل رابط نفق جديد.
- **مصدر واحد للحقيقة:** `stream-embed.conf` (`player = https://<مضيف-النفق>`) —
  سطر واحد يتغير عندما يتغير رابط النفق. الوسيط لا يقبل رابطًا من الزائر إطلاقًا
  (`?u=` اسم مستعار من قائمة مغلقة، و`?p=` مسار فقط).
- **الأمان:** مضيف الأصل يجب أن يكون مسموحًا في `allowed-domains.txt` (مطابقة تامة
  أو مضيف فرعي بحد فاصل عند النقطة، فيكفي تسجيل `trycloudflare.com`)، وكل عناوين
  DNS له يجب أن تكون عامة (منع SSRF)، والتحويلات لا تُتبع تلقائيًا (كل قفزة تُفحص،
  والتحويل لمضيف آخر يُعاد للزائر 302)، مع حد معدّل للطلبات.
- **إعادة الكتابة:** روابط HTML الجذرية (`/assets/app.js`) تتحول إلى
  `/player/assets/app.js` حتى تبقى داخل الوسيط؛ النسبية تُترك (يحلها المتصفح مقابل
  `/player/<dir>/`)، والكاملة `https://…` تُترك (البث نفسه يمر عبر CDN خارجي تسمح به
  سياسة الموقع). `srcset` يُعالج مرشّحًا مرشّحًا، والبادئة لا تُضاعف.
- **رؤوس الاستجابة:** `.htaccess` يلغي CSP و`X-Frame-Options` للموقع عن `embed.php`
  فقط (وإلا حُجب المشغّل داخل الإطار)، و`embed.php` يرسل سياسة أمان خاصة به
  (ترويسة + وسم `<meta>`) على المستند المُضمَّن. الوسائط تُبث متدفقة مع الحفاظ على
  `Range` و`Content-Length`، وHTML وحده يُخزَّن في الذاكرة (≤4MB).
- **الفهرسة:** `noindex` في الصفحة + `Disallow: /player.html` و`/player/` و`/embed.php`
  في `robots.txt` + `X-Robots-Tag: noindex` للوسيط. الصفحة غير مربوطة من القوائم.
- **الحدود المعروفة:** الوسيط يمرّر مستندات وأصولًا ثابتة؛ الروابط المبنية داخل
  JavaScript بمسارات جذرية، وعناوين WebSocket المطلقة، وService Worker لا تُعاد
  كتابتها. ولو احتاج المشغّل ذلك فالحل تثبيت ملفاته داخل المستودع بدل النفق.
- **التحقق:** `scripts/test-embed-php.mjs` (16 فحصًا) يشغّل القواعد الحساسة من
  `scripts/embed-rewrite.mjs` (قراءة الإعدادات، قائمة النطاقات، حل الرابط ومنع
  الخروج من الأصل، إعادة كتابة HTML و`srcset` وحقن CSP)، ويفحص أن `embed.php`
  يحمل القواعد نفسها، وأن بنيته سليمة (ماسح أقواس/سلاسل بدل `php -l` غير المتاح
  في CI)، وأن الصفحة والقواعد في `.htaccess` و`robots.txt` و`_headers` متفقة.
  **سلوك `embed.php` الفعلي مع النفق لم يُختبر** — لا PHP ولا وصول للشبكة في بيئة
  الاختبار؛ يلزم فتح `/player.html` على الاستضافة للتأكد.

## مشغّل اشتراكك الشخصي — تطوير القسم (`#xtream`)

منطق القسم انتقل بالكامل إلى `website/src/lib/xtream.mjs` (دوال خالصة، بلا DOM
وبلا React) وأنواعه في `website/src/lib/xtream.d.mts`، وبقي
`website/src/components/XtreamPlayer.tsx` للواجهة فقط. الهدف: منطق واحد مُختبَر
يُعاد استخدامه، لا نسخة مكرّرة داخل المكوّن.

### ما أُضيف

- **تعدد الحسابات:** قائمة حسابات محفوظة (`smp-xtream-accounts`) مع شرائح للتبديل
  الفوري وحذف حساب. الجلسة القديمة (`smp-xtream-account`) تُهاجَر تلقائياً إلى القائمة،
  وتبقى مكتوبة للتوافق مع الإصدار السابق.
- **مفضلة وسجل مشاهدة لكل حساب على حدة** (`smp-xtream-favorites`، `smp-xtream-recents`)
  بمفتاح ملف (`profileKeyFor`) لأن أرقام القنوات تختلف من مزوّد لآخر — لا تختلط قوائم
  حسابين، وملف M3U له ملف مستقل.
- **بحث عربي موحّد** (`normalizeArabic` + `matchesQuery`): الهمزات والتاء المربوطة
  والياء والتشكيل والأرقام العربية، وكل الكلمات بلا ترتيب، ويعمل على **كل** القنوات في
  كل التصنيفات لا داخل التصنيف المختار فقط.
- **قائمة قنوات افتراضية (Virtual):** أُزيل سقف «أول 300 قناة» (`list.slice(0, 300)`)
  واستُبدل بحساب نطاق الرسم (`windowRange`) وصف بارتفاع ثابت، فأي عدد قنوات يُعرض بسلاسة
  مع بقاء عدد عناصر DOM صغيراً.
- **أدوات المشغل:** اختيار الجودة من مستويات hls.js، صورة داخل صورة، ملء الشاشة،
  وعدّاد الأيام المتبقية في الاشتراك (`daysUntil`) مع تنبيه عند 7 أيام أو أقل.
- **تقرير تشخيص قابل للمشاركة:** `createShareToken` يبني رمزاً قصيراً (`SMP1.…`)
  بلا كلمة سر واسم مستخدم مقنّع (`maskUsername`)، مع نسخ الرمز أو إرساله للدعم عبر
  واتساب (`WHATSAPP_NUMBER` في `src/config.ts`).
- سحب ملف M3U وإفلاته، وإصلاح ترتيب رسائل الفشل: كل المحاولات المنتهية بمهلة تُوصف
  بأنها «لا استجابة» بدل نسبتها إلى حجب CORS.

### النسخة الجديدة — ثلاث قوائم ومزايا مشغّل احترافي (2026-10)

- **ثلاثة أقسام:** البث المباشر (كما كان) + **الأفلام** (`get_vod_categories` /
  `get_vod_streams` / `get_vod_info` — بوستر، قصة، تقييم، طاقم التمثيل، إعلان، تشغيل
  mp4/mkv) + **المسلسلات** (`get_series_categories` / `get_series` / `get_series_info`
  — مواسم وحلقات مع **متابعة المشاهدة** `smp-xtream-resume` وشارة «متابعة» بجانب كل
  حلقة محفوظة).
- **دليل البرامج EPG:** `action=get_short_epg&stream_id=X&limit=4` مع فك Base64 الآمن
  للعربية (`decodeEpgField`)، شريط «يعرض الآن… التالي…» مع نسبة تقدّم (`parseShortEpg`
  + `EpgBar`) يتحدث كل 5 دقائق أثناء تشغيل قناة مباشرة.
- **mpegts.js 1.8.2** (تحميل كسول منفصل `src/mpegts.ts`، chunk خاص) لروابط MPEG-TS
  الخام `.ts` — hls.js يبقى لـ m3u8 والتشغيل الأصلي لـ mp4/mkv، بنفس سلّم المرشّحين
  وسقوط التلقائي (الخلية `StageCell.tsx`).
- **تنقّل ريموت/كيبورد:** ↑↓ (وPageUp/PageDown) تبديل القنوات بتجوّز، ←→ الصوت في
  المباشر أو ±10 ثوانٍ في الأفلام، `F` ملء الشاشة، `M` كتم، `Space` إيقاف/تشغيل،
  وكتابة أرقام رقم القناة (timeout 1.3 ثانية، `findChannelByNumber` على حقل `num`)؛
  أزرار داخل الفيديو: القناة السابقة/التالية + زر «القنوات» يفتح **درج القنوات داخل
  الشاشة** (يعمل داخل ملء الشاشة) مع شاشة OSD للرسائل.
- **عدة الشاشات:** 1 / 2 / 4 شاشات (`view-1/2/4`) — كل شاشة خلية تشغيل مستقلة،
  والنقر على أي شاشة ينقل الصوت إليها فقط (بقية الخلايا مكتملة دائماً).
- **مسارات صوتية وترجمة وأوضاع عرض:** اختيار الصوت والترجمة من `hls.audioTracks` /
  `subtitleTracks`، رفع ملف **SRT/VTT** محلياً (`srtToVtt` → blob `<track>`)، وأوضاع
  العرض 16:9 و4:3 وFill وContain (`ASPECT_MODES` + `aspectStyle`).
- **Chromecast/AirPlay:** كشف إمكانية الجهاز (Remote Playback API +
  `webkitShowPlaybackTargetPicker`) مع اختباري `cast-button`/`airplay-button`.
- **إعادة البث Catch-up/Timeshift:** للقنوات التي تعيد `tv_archive` — خيار آخر 2/6/12
  ساعة يبني روابط `/timeshift/{u}/{p}/{id}/{YYYY-MM-DD:HH-mm}/{دقائق}.m3u8`
  (`timeshiftUrl`).
- **القفل الأبوي:** رمز 4 أرقام يُخزَّن Hashed (`hashPin`) مع اختيار التصنيفات المراد
  قفلها (مباشر/أفلام/مسلسلات) — فتح تصنيف مقفل يطلب الرمز (`PinDialog`).
- **حفظ القوائم في IndexedDB** (`src/lib/idb.ts`، قاعدة `smp-xtream`): الزيارة الثانية
  تفتح بـ«فتح فوري» بدل تنزيل آلاف القنوات، مع وسم «محفوظة محلياً» وزر
  **«تحديث القنوات»** (`refresh-channels`) لإعادة الجلب وتحديث النسخة. كل عمليات
  التخزين بمهلة 2 ثوانٍ — أي تعطّل فيها لا يؤخر تسجيل الدخول أبداً.
- **مسارات متعددة للاتصال موحّدة مع صفحة البث المباشر:** كل استدعاءات الواجهة الجديدة
  (EPG، الأفلام، المسلسلات) تمر عبر `buildModes` نفسها (مباشر → Worker `/h/` `/x/` →
  `/proxy.php`) والمسار الناجح يُفضَّل تلقائياً في الجلسة (`preferredStreamModeRef`).

### بصمة المشغّل — User-Agent الخاص بـ IPTV Smarters/VLC (2026-10)

مشغّل الصفحة الرئيسية (`#xtream`) صار **يُجرّب بصمة مشغل IPTV** عندما يرفض السيرفر
الاتصال القادم من متصفح، لأن كثيراً من لوحات Xtream وشبكات CDN تحجب متصفحات الويب
صراحةً (403/406) وتسمح فقط لمشغلات IPTV المعروفة.

- **القيمة المستخدمة (حرفياً):** `iptv_smarters_player_lite/1.4.2 VLC/3.1.2 LibVLC/3.1.2`
  معرّفة مرة واحدة في `website/src/lib/xtream.mjs` (`SMARTERS_USER_AGENT`) ومرة في
  `proxy.php` (`UA_PRESETS`) و`website/proxy/worker.js` (`UA_PRESETS`) —
  و`scripts/test-proxy-php.mjs` يقارن النصوص الثلاثة فلا تتباعد.
- **لماذا عبر الوسيط؟** المتصفح يعتبر `User-Agent` رأساً محظوراً: لا `fetch` ولا
  `XMLHttpRequest` ولا `xhrSetup` في hls.js تستطيع تغييره. لذلك يطلب المشغّل البصمة
  من الوسيط بمعامل `?smpua=smarters`، والوسيط (البروكسي أو Worker) هو الذي يرسلها
  للسيرفر الأصلي. **الاتصال المباشر لا يحمل البصمة إطلاقاً** — لا فائدة منها هناك.
- **سلّم المحاولات (`addUaVariants`):** بعد كل مرشّح يمر عبر وسيط تُضاف نسخة تحمل
  البصمة، بالترتيب: مباشر ← وسيط Worker ← *Worker + البصمة* ← `/proxy.php` ←
  *`/proxy.php` + البصمة* ← تشغيل أصلي. ولو نجحت البصمة في تشغيل، تُقدَّم على
  نسختها العادية في كل تشغيل تالٍ ضمن الجلسة (`preferredUaRef` عبر
  `onPreferredUa` في `StageCell.tsx`)، وتظهر شارة `ua-badge` بقيمتها في `title`.
- **القائمة مغلقة:** الوسيط لا يقبل إلا `smarters`؛ أي قيمة أخرى تُتجاهل ويُرسل
  `User-Agent` المتصفح كما كان (لا يصبح البروكسي أداة تمويه عشوائية).

ما يحافظ عليه الوسيطان أثناء ذلك (وهو سبب نجاح البصمة عملياً):

- **متابعة تحويل `302`:** `proxy.php` يتابع `301/302/303/307/308` يدوياً حتى 5 قفزات
  مع `validate_url` لكل وجهة (منع SSRF) وحلّ الروابط النسبية، و**بصمة واحدة ثابتة
  لكل القفزات** — بعض السيرفرات تربط الجلسة بالبصمة فتغييرها بعد التحويل يُبطلها.
  و`worker.js` يعتمد `redirect: "follow"` بنفس الرؤوس. جسم رد التحويل لا يُبث للزائر
  (كان يُخلط بأول بايت من المقطع).
- **الحفاظ على `Range`:** يُمرَّر كما هو للسيرفر الأصلي ويبقى عبر كل قفزة تحويل،
  ويعيد `proxy.php` الآن **حالة الرد الحقيقية (206 Partial Content)** مع
  `Content-Range`/`Accept-Ranges`/`ETag`/`Last-Modified` — سابقاً كان يرد 200 دائماً
  فيفشل التقديم/التراجع في الأفلام وترفض بعض المشغلات المقاطع الجزئية. رؤوس قفزات
  التحويل تُصفَّر عند كل سطر حالة جديد، و`Content-Length` يُمرَّر فقط ضمن حد
  `MAX_BYTES` حتى لا نعد بطول لا نسلّمه.
- **معاملات جلسة قائمة HLS:** `rewrite_m3u8` (و`rewriteManifest` في Worker) تنسخ
  معاملات جلسة القائمة النهائية (بعد التحويلات) — مثل `?token=…` — إلى كل مقطع
  وقائمة فرعية ومفتاح فك تشفير **على نفس المضيف ولا يحمل استعلاماً خاصاً**، وتحفظ
  `smpua` في كل رابط مولّد؛ فلا يفتح السيرفر جلسة جديدة لكل طلب ولا تُكسر روابط CDN
  الموقّعة التي تحمل توقيعها الخاص. ومعاملات الوسيط نفسها (`smpua`) تُحذف من
  استعلام السيرفر الأصلي في مسار `/h/` و`/x/`.
- **كوكيز الجلسة بين القفزات:** أي `Set-Cookie` من قفزة يُعاد في القفزة التالية
  (جرة في الذاكرة داخل الطلب الواحد — لا تُكتب على القرص ولا تُخزَّن بين الطلبات).

**متطلبات الإنتاج:** البصمة تعمل على الاستضافة التي تشغّل PHP (`/proxy.php`) أو عبر
Worker منشور من `website/proxy/worker.js` الجديد. النشر الضروري للوسيط يبقى يدوياً
(`npx wrangler deploy`)؛ ولو عمل الموقع بوسيط قديم فلا ينكسر شيء — يُتجاهل `smpua`
كأي معامل غير معروف ويبقى السلوك كما كان.

### إصلاحان خارج نطاق القسم

- **لا إرسال أصلي قبل التحميل:** كان النموذج `<form>` مع `onSubmit` — وقبل انتهاء
  hydration (الصفحة مرسومة مسبقاً) يؤدي أي إرسال أصلي إلى إعادة تحميل الصفحة ووضع
  اسم المستخدم وكلمة السر في الرابط وسجل الخادم. صار حاوية `role="form"` مع زر
  `type="button"` ومعالجة Enter يدوياً، فالنقر قبل التحميل بلا أثر ولا سرّ في الرابط.
- **روابط الأقسام تصل فوراً:** `useHashScroll` في `HomePage.tsx` يعيد التمرير بعد أول
  إطار وبعد اكتمال التحميل، وبسلوك `instant` ليتجاوز `scroll-behavior: smooth`،
  وصفحات React صارت تحترم `prefers-reduced-motion` في التمرير كما تفعل صفحات المتجر
  القديمة. (كان الانتقال إلى `/#faq` من صفحة أخرى يفشل أحياناً.)

### التحقق

```sh
npm test           # 80 فحصاً — منها 41 لمشغّل الاشتراك في scripts/test-xtream.mjs
                   # و13 لوسيط Worker و8 لعقد proxy.php (بصمة المشغّل/302/Range/الجلسة)
npm run typecheck
npm run test:ui -- tests/xtream-player.spec.ts    # 10 اختبارات للقسم (EPG + الأفلام/المسلسلات + عدة الشاشات + بصمة المشغّل)
```

`website/tests/xtream-player.spec.ts` يعمل بمحاكاة كاملة للسيرفر (400 قناة) ويقطع كل
اتصال خارجي، ويستعمل `serviceWorkers: 'block'` لأن عامل الخدمة كان يعترض طلبات
المحاكاة خارج نطاق `page.route`، وينتظر اكتمال hydration قبل التفاعل. الاختبارات
تتحقق من الواجهة والمنطق المحلي فقط، **ولا تثبت صلاحية بث أي مزوّد** ولا عمل الوسيط.

اختبار البصمة (`المشغّل يجرّب بصمة Smarters/VLC…`) يحاكي سيرفر يرفض كل طلب بلا بصمة
(403) ويقبلها عبر `/proxy.php`، ويتحقق من: وصول طلب `smpua=smarters` فعلاً، وأنه يأتي
**بعد** محاولة المسار نفسه بلا بصمة، وأن الاتصال المباشر بالسيرفر لا يحمل المعامل،
وأن شارة `ua-badge` تظهر بالقيمة الحرفية للبصمة. سلوك `proxy.php` الحقيقي مع السيرفرات
(التحويل، `Range`، الجلسة) لا يُختبَر هنا لأنه يحتاج PHP وشبكة — تغطيه فحوص المصدر أعلاه.

### ملاحظات تبقى قائمة

- مسار الملف M3U لا يزال يستعمل `PROXY_BASE` في `m3uCandidates` كمرشّح أخير. تمرير بث
  المشترك عبر سيرفر يخصّنا هو النقطة الأضعف قانونياً في هذا القسم، وإزالته تحتاج قراراً
  منفصلاً لأنها قد تُفقد بعض المشتركين التشغيل.
- إعادة البث Timeshift تعتمد على نمط `/timeshift/` الشائع في لوحات Xtream — بعض
  اللوحات لا تدعمه فتسقط تلقائياً على بقية المرشّحين ثم رسالة خطأ واضحة.
- مسارات غير منفَّذة بعد من خطة التطوير: «افحص حالة اشتراكك» كصفحة تسويقية، النسخة
  البيضاء، والتضمين للشركاء.
