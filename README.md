# Stream Master Pro — التصميم الجديد

أُعيد تصميم واجهة المتجر باستخدام ملفات الموقع المرجعي الذي حدده صاحب المشروع:
`ahmedlasheenrespicare-png/serverproject`، الإصدار `48c72d057df8e1917c9a18e4bfdd436adfd94d25`.

## ما تغير

- تصميم RTL بخلفية كريمية، نص داكن، ولمسات ليمونية وبنفسجية؛ نفس أقسام الرئيسية والحركات والصور والخطوط المحلية للموقع المرجعي.
- صفحات الرئيسية، المتجر، السيرفرات، القنوات، المدونة، الأسئلة الشائعة والسلة مبنية بمكونات React مشتركة ومولّدة مسبقاً إلى HTML.
- المقالات العربية القديمة، صفحات السياسات، البحث، حالة الخدمة، التوقعات وكأس العالم والبث المجاني احتفظت بروابطها ومحتواها وسكربتاتها، مع واجهة وألوان مشتركة جديدة.
- بقيت العروض السنوية المعروضة في المتجر: نوفا **25 دولار**، إيستار **35 دولار**، موكا **45 دولار**. لم تُستورد عروض وأسعار المرجع؛ تحويل العملات تقديري بالأسعار الثابتة الموجودة في الإعدادات، وليس سعراً مصرفياً لحظياً.
- بقي رقم واتساب الموقع `201098950879`. السلة تُحفظ محلياً وتستورد العناصر السنوية من السلة القديمة، ثم تعيد حساب أسعارها من الكتالوج.
- لم تُعدّل ملفات PHP أو لوحة الإدارة أو قائمة النطاقات المسموح بها.
- الهيدر منظم في خمس قوائم منسدلة — الرئيسية (كل أقسامها)، السيرفرات والباقات، القنوات والبث، المقالات، المساعدة — ويضم كل صفحات الموقع. الهيدر الجديد وهيدر الصفحات القديمة يُبنيان من `website/src/navigation.mjs`؛ أضف أي صفحة جديدة هناك فقط.
- دُمجت قنوات تصنيف «قنوات MBC» (13 قناة: MBC 1، MBC Masr 1/2، MBC Masr Drama، MBC Drama، MBC 4، MBC 5، MBC Bollywood، MBC Persia، العربية، الحدث، العربية أسواق، MBC Loud FM) من `channels.json` في الموقع المرجعي إلى أعلى `channels.json`، وصُححت روابط ثلاث قنوات في `FEATURED_CHANNELS` لتطابق المرجع.

## التشغيل

يتطلب Node.js 22:

```sh
npm run setup       # تثبيت الاعتمادات من website/package-lock.json
npm run build       # بناء React + SSR، ثم تحديث ملفات النشر في جذر المستودع
npm run preview     # معاينة جميع الصفحات على 0.0.0.0:3000
```

`npm run dev` يشغّل Vite لتطوير صفحات React فقط. لمعاينة الصفحات القديمة وملفات القنوات معاً، استخدم البناء ثم `npm run preview`.

## أماكن التعديل

| المسار | الغرض |
| --- | --- |
| `website/src/components/` | مكونات التصميم المرجعي |
| `website/src/pages/` | صفحات React |
| `website/src/config.ts` | النطاق والهوية ورقم التواصل والوسيط |
| `website/src/data.ts` | الكتالوج والعملات والقنوات المميزة |
| `website/src/navigation.mjs` | روابط الهيدر وقوائمه المنسدلة لكل الصفحات (React والصفحات القديمة معاً) |
| `website/src/content/` | المقالات الجديدة وفهرس المقالات القديمة |
| `website/public/` | الصور والخطوط وطبقة تصميم الصفحات القديمة |
| `website/legacy/` | مصادر الصفحات القديمة المحفوظة، قبل إضافة الغلاف الجديد |
| `website/scripts/legacy-shell.mjs` | رأس وتذييل الصفحات القديمة |
| `website/scripts/publish-static.mjs` | نشر مخرجات البناء محلياً إلى جذر المستودع |

**لا تعدّل HTML المولّد في الجذر مباشرة**؛ عدّل مصدره ثم أعد البناء. الملفات المولّدة تحت `_assets/redesign/` وملفات HTML محفوظة في Git عمداً، لأن الاستضافة الحالية تنشر موقعاً ثابتاً من جذر المستودع.

## التحقق

```sh
npm run typecheck
npm test            # اختبارات قارئ القنوات والوسيط
npm run test:ui     # اختبارات Chromium: الجوال، السلة، التنقل، النوافذ والروابط القديمة
```

اختبارات المتصفح تمنع الاتصالات الخارجية عمداً. لا تثبت هذه الاختبارات صلاحية بث القنوات أو وصول رسائل واتساب. معاينة Node ثابتة ولا تشغّل PHP؛ يلزم فحص البث وواجهات الإدارة على استضافة تدعم PHP. لم يُنشر Cloudflare Worker جديد؛ مصدره المرفق من المرجع للاختبارات فقط.

## النشر

سير عمل Hostinger الحالي أصبح يبني الموقع قبل رفعه عند التحديث على `main`، ويستثني `website/` والاعتمادات من الرفع. هناك أيضاً فحوص البناء والواجهة لطلبات الدمج وفروع Arena. هذه التعديلات لا تنشر الموقع أو تدمج الفرع تلقائياً.

ملاحظة: نموذج تحديثات العروض يفتح طلباً عبر واتساب؛ لا يدّعي إرسال بريد إلكتروني دون وجود خدمة بريد خلفية. قائمة البث الإضافية `kora-live.m3u8` تبدأ فارغة عمداً، ولم تُنسخ بيانات بث خاصة من المرجع. البث المجاني الحالي وقائمة قنواته الأصلية باقيان.

## صفحة مواعيد المباريات — `/matches/`

- مصدر الواجهة: `website/src/pages/MatchesPage.tsx`، والتصميم: `website/src/pages/matches.css`.
- التاريخ في المتصفح يُحسب حسب المنطقة المختارة؛ يعرض الشريط ١٥ يومًا (٧ سابقة + اليوم + ٧ قادمة) ويتجدد عند منتصف الليل. لا تُثبت التواريخ أثناء البناء.
- المواعيد بتوقيت مكة ومصر وUTC ظاهرة في كل بطاقة، مع اختيار بقية مناطق IANA العالمية وحفظ الاختيار محليًا. تحويل `Intl` يراعي التوقيت الصيفي في مصر، وتُعرض تواريخ كل منطقة إذا اختلف اليوم.
- المصدر هو واجهة ESPN العامة `https://site.api.espn.com/apis/site/v2/sports/soccer/{league}/scoreboard`. البطولات المغطاة مذكورة صراحة في `website/src/lib/matches.mjs`؛ ليست تغطية لكل مباريات العالم. أسماء الفرق تأتي كما يرسلها المصدر، وقد تكون بالإنجليزية.
- الصفحة تُحمّل اليوم المختار مع اليوم السابق والتالي بتوقيت UTC ثم تُصفي حسب المنطقة الزمنية، لتجنب فقد مباريات قرب منتصف الليل. التحديث كل ٦٠ ثانية أثناء ظهور الصفحة واتصالها بالإنترنت، مع زر تحديث فوري وإمكانية إيقاف التحديث الدوري. لا تُحسب النتائج أو دقائق اللعب تخمينيًا.
- فشل المصدر أو بطولة معينة له تنبيه منفصل عن اليوم الخالي من المباريات. تُحفظ آخر بيانات اليوم نفسه أثناء فشل التحديث، وتُوسم بأنها قديمة؛ لا تُحفظ النتائج في Service Worker.
- **متطلبات الإنتاج:** تعمل الصفحة على الاستضافة الثابتة دون مفاتيح API أو PHP، ولكن يلزم أن يستطيع متصفح الزائر الوصول إلى ESPN وأن تسمح الخدمة بـCORS. هذه واجهة عامة غير مضمونة الاستمرار أو التغطية أو زمن تحديث النتائج. لا توجد بيانات مباريات وهمية منشورة ولا مفتاح API داخل الملفات. للحصول على ضمانات وتغطية محددة يلزم مزود بيانات مرخّص ووسيط خلفي بمفتاح سري.
- **حدود التحقق:** الاتصالات الخارجية في اختبارات المتصفح محاكاة ببيانات اختبار فقط؛ بيئة العمل لا تسمح باتصال ESPN، لذا لا تثبت الاختبارات صلاحية المصدر الفعلي أو توافر بطولة بعينها. يلزم فحص `/matches/` من متصفح على الموقع المنشور قبل الاعتماد عليه كخدمة حية.
- `npm test` يتحقق من قارئ النتائج، حدود الأيام والتوقيت الصيفي. `website/tests/matches.spec.ts` يتحقق من التحديث التلقائي، التصفية والتواريخ والمناطق الزمنية والأخطاء والجوال والتنقل.
