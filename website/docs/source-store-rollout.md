لا تغيير في المزوّدين أو القوائم أو بنية `events` وحقول الترتيب، ولا تعديل لقواعد قبول صفوف الترتيب أو حساباتها في JS/PHP.

**لا تجميد تلقائي لجدول الترتيب**: انتهاء يوم أو جولة لا يثبت انتهاء موسم البطولة. المصادر الحالية/الإعداد الحالي لا تحمل في هذا التنفيذ دليلاً نهائياً معتمداً لذلك. تجميد الموسم يحتاج تعريفاً وموافقة مستقلين، ولا يُختلق هنا.

اكتشاف حالة الترتيب قراءة فقط للملفات الموجودة، بلا طلب إضافي للمصدر. يقتصر على يوم UTC الحالي، ودليل عمره أقل من 600 ثانية وغير مستقبلي. لـ egy.1 تُقرأ جولات 4829، ولـ ESPN ملف اليوم. لا alias بين `ksa.1` و`sau.1`؛ ولذلك ksa.1 يبقى 900 ثانية لعدم وجود ملف مباريات مسموح له. غياب الملف أو تقادمه يعني عدم وجود دليل مباشر، لا افتراض وجود مباراة جارية. ظهور دليل مباشر يقصّر صلاحية نسخة ترتيب كانت 900 إلى 120 من آخر فحص ناجح.

### حدود الاحتياط

- عمر الاحتياط محسوب من `fetched_at` الناجح، **لا** من `checked_at` ولا من كتابة رد مجمّع.
- مباريات ESPN وsummary: 600 ثانية. جولات TheSportsDB ذات TTL=60: 600 ثانية، وغير ذلك بلا سقف إضافي كما في PR #54. الترتيب: 86400 ثانية.
- نتيجة لذلك قد لا تتوافر نسخة صالحة للاحتياط عند أول فشل لتحديث يوم ESPN مجدول عمره 900 ثانية: هذا تطبيق لحد المباريات الحالي 600، لا تمديد خفي له.
- تُسجّل الأخطاء حتى بلا نسخة ناجحة، أو بعد انتهاء سقف الاحتياط؛ لا تتكرر المحاولة داخل النافذة. رد STALE لا يدخل كاش الاستجابة الطازج.
- ثوابت طبقات الرد محفوظة: `CACHE_TTL=45` و`STALE_TTL=600`، `MC_CACHE_TTL=45` و`MC_STALE_TTL=600`، و`SM_ST_TTL=120` و`SM_ST_STALE_TTL=86400`.
- كاش رد مركز المباراة 45 ثانية مستقل عن ملفات المصدر. فشل summary لا يمحو النتيجة الصحيحة، لكنه يوسم الرد STALE مع التشخيص، ولا يخزّنه طازجاً. إذا فشل الجدول الأساسي بلا احتياط صالح يرجع خطأ.

## تجهيز الاستضافة — قبل الدمج

1. اختر مجلداً خاصاً مطلق المسار **خارج public_html وجذر الموقع**، وأنشئه بصلاحية 0700 لمالك PHP. اضبط `SM_DATA_DIR` في بيئة PHP-FPM/Hostinger وتحقق من ظهوره لطلبات الويب، لا CLI فقط. لا تضبطه على جذر المستودع.
2. عند غياب الإعداد: مجلد النظام المؤقت `/smp_source_store` تحت `sys_get_temp_dir()`، مع سجل `SM_DATA_DIR_UNSET`. الإعداد غير الآمن ينتقل للمؤقت مع `SM_DATA_DIR_UNSAFE` دون تسجيل قيمة المسار.
3. اضبط **`SM_SPORTSDB_KEY`** من البيئة، أو ضع المفتاح في `<المجلد الأب لجذر الموقع>/SM_SPORTSDB_KEY/key.txt` بصلاحية 0600. لا يوجد مفتاح افتراضي في الكود الآن؛ الغياب/القيمة غير الصالحة ينتج `UPSTREAM_KEY_MISSING` دون طلب الشبكة. استخدم المفتاح المجاني الذي تختاره من إعداد الخادم إن بقيت عليه؛ لا قيمة سرية في هذا المستند.
4. Highlightly لم يتغير: `SM_HIGHLIGHTLY_KEY` أو `<المجلد الأب لـ DOCUMENT_ROOT>/SM_HIGHLIGHTLY_KEY/key.txt`.
5. لا تطبع البيئة أو المفاتيح ولا تضعها في رابط فحص أو سجل. لا تُشغّل curl بوضع verbose يتضمن الترويسات السرية.

### المجلدات والانتقال

داخل `SM_DATA_DIR`: `espn-days/`، `espn-summaries/`، `smp_sportsdb_rounds/`، `standings/`، `scoreboard-responses/`، `match-center-responses/`.

كل سجل مصدر يحمل `schema`, `checked_at`, `fetched_at`, `ttl`, `frozen`, `error`, `payload`؛ الفشل قبل أول نجاح يحمل fetched_at/payload = null. حقول إضافية تضبط الاحتياط/المحاولة وHTTP الخطأ فقط. الكتابة ملف مؤقت 0600 ثم rename في المجلد نفسه، والقفل لكل وحدة، والكتابة قبل فكّه. القفل لا يُحذف في تنظيف كاش الردود حتى لا يُنشأ inode قفل ثانٍ أثناء طلب جارٍ. وحدات المصدر المجمدة لا يحذفها تنظيف الردود.

ملفات جولات PR #54 الموجودة تحت `SM_DATA_DIR/smp_sportsdb_rounds` تُحوّل من `events` إلى `payload.events` تحت القفل، مع الاحتفاظ بالوقت والتجميد؛ لا إعادة جلب للجولة المجمدة. إن لم يكن SM_DATA_DIR مضبوطاً سابقاً، انسخ الجولات القديمة من مجلد النظام المؤقت القديم إلى المسار الخاص الجديد **أثناء إيقاف/تصريف العمال**. كاش الترتيب القديم `/sm-standings-v1/<league>.json` يمكن نسخه إلى `standings/` بالطريقة نفسها، وتُحوّل سجلات storedAt/raw تلقائياً عند قراءتها تحت القفل؛ لا تنقل أي ملف غير موثوق. كاش الردود القديم غير مطلوب ويبدأ بارداً (`v6`). لا تحذف ملفات القفل مع وجود عمال نشطين.

## الاختبار القابل للإعادة

من جذر المستودع، Node 22:

```sh
npm ci --prefix website
npm ci --prefix tests/source-store
npm test --prefix tests/source-store
npm run typecheck
npm test
npm run build:client --prefix website
```

`tests/source-store` له lockfile مستقل يثبت `@php-wasm/node` و`@php-wasm/universal`؛ لا تُضاف هذه الاعتمادات إلى بناء واجهة الإنتاج. الاختبار داخل VFS مستقل، بلا شبكة وبلا بيانات استضافة. GLOB_BRACE يُستبدل في نسخة الاختبار فقط، ولا تعديلات توافق خاصة بـ WASM على كود الإنتاج. اختبار curl_multi يستخدم namespace مع doubles لدوال الامتداد؛ ليس اتصال cURL حقيقياً. بقيت ملفات الكنترولر في فحوص HTTP دون إعادة كتابة منطقها. تعاد تسمية رموز نسخة standings القديمة لاختبار قبل/بعد بالمدخلات نفسها.

النتائج المحلية الفعلية:

- PHP **8.3.30**: **242 assertions** + فحوص HTTP وترويسات الكاش ونسخ النشر؛ كلها ناجحة.
- اختبارات المشروع: **374/374**، دون skipped، بما فيها runtime الترتيب عبر محوّل PHP 8.3.
- المطلوب تحديداً: matches **9/9**، match-center PHP **17/17**، proxy PHP **8/8**.
- TypeScript: ناجح. build:client: ناجح مع تحذير حجم chunks الحالي.
- تطابق before/after normalization لملفات اللقطة نفسها للبطولات الثماني بالحقول والقيم والترتيب؛ تغيير التشخيص للصفوف الناقصة فقط إلى `UPSTREAM_INCOMPLETE`.
- الاختبارات تغطي الساعة والحالات، تجميد وانتقال انتهاء حديث إلى مجمد، المؤجلة/الملغاة، البحث الثنائي، مشاركة الأيام والنوافذ، مسار curl_multi بوحدتين مستحقتين، حدود 499/500/501 و15، HTTP/429/timeout/network/JSON، stale وحدوده والتأجيل حتى بلا نسخة، الأسرار في الأخطاء والسجلات، والبيانات الغائبة.

الفحوص البنيوية القديمة عُدّلت لتعقب المكتبات المشتركة بدلاً من اشتراط أن تكون كل الدوال داخل ملف واحد؛ لم تُحذف حالات الاختبار. ملفات الترتيب في الجذر وwebsite/public وكذلك source_store متطابقة بفحص صريح حتى لا يلغي البناء التغيير. verify CI يشغّل مجموعة PHP الجديدة، والنشر يستبعد tests/**.

الاختبارات ليست فحص تزامن PHP-FPM متعدد العمال على Hostinger، ولا إثبات سلوك شبكة المصادر الحقيقية. تلك تبقى ضمن تحقق الاستضافة.

## تحقق Hostinger بعد النشر — مطلوب وغير منفذ بعد

شغّل من **الخادم نفسه**. لا تتوقع نجاح curl من بيئة الوكيل ذات قائمة النطاقات المحدودة. لا تُسجل النتائج المفترضة كفعلية.

1. سجّل commit المنشور ووقت بدء نافذة الساعة الأولى UTC والمسار الفعلي المختار لـ SM_DATA_DIR (بدون أسرار).
2. اطلب scoreboard مرتين متتاليتين خلال 45 ثانية ليوم فيه مباريات (ابدأ 20261017، وإن كان فارغاً استخدم يوماً مثبتاً لكل بطولة):
   `eng.1 esp.1 ita.1 ger.1 fra.1 uefa.champions uefa.europa fifa.worldq.caf fifa.worldq.uefa fifa.friendly egy.1 sau.1`.
   مثال: `/scoreboard.php?league=eng.1&dates=20261017`.
3. سجل HTTP، عدد events، `X-Matches-Cache`، `X-Cache-Age`، `X-Diagnostic-Code`، وبصمة الحمولة في الطلبين. المنتظر لكاش رد بارد ناجح MISS ثم HIT؛ إن كانت النسخة دافئة مسبقاً قد يكون HIT في كليهما، فلا تحذف وحدات المصدر المجمدة لمجرد الحصول على MISS.
4. افحص `/match-center.php?match=<slug مسجل>` مرتين وسجل `X-Match-Center-Cache` والتشخيص؛ طابق يومه وبطولته مع ملف ESPN المشترك وعدد محاولات المصدر (لا جلب مكرر من صفحتي المباريات والمركز).
5. افحص `/standings.php?league=...` لكل:
   `eng.1 esp.1 ita.1 ger.1 fra.1 uefa.champions ksa.1 egy.1`.
   **ترتيب الصفحة يحتفظ بترويسته الأصلية X-Standings-Cache** وحقول cache/code/stale/ageSeconds، وليس X-Matches-Cache. المنتظر MISS ثم HIT داخل 120/900 بحسب الدليل؛ لا طبقة رد 45 ثانية جديدة للترتيب.
6. سجل عدد ملفات JSON لكل namespace تحت SM_DATA_DIR، وتأكد من عدم وجود ملفات بيانات تحت public_html؛ استثنِ ملفات PHP المكتبات نفسها فهي كود وليست بيانات. صلاحيات القراءة والكتابة تخص مالك PHP فقط.
7. محاولات الجلب تُسجل بدون URLs أو مفاتيح بصيغة:
   `SM_SOURCE_REQUEST unit=espn-days/eng.1-20261017.json at=<unix>`
   خذ فقط السطور ضمن ساعة البداية والنهاية، واجمع حسب namespace/league. للجولات: 4829=egy.1 و4668=sau.1. summary تُحسب منفصلة كي لا تختلط بجدول المباريات؛ standings منفصلة كذلك. كل سطر SM_SOURCE_REQUEST = بدء طلب HTTP واحد؛ curl_multi قد يحتوي عدة وحدات لكنه ليس طلباً واحداً. أسطر SM_SOURCE_FETCH تسجل نتيجة فحص الوحدة، وقد تسجل فشلاً قبل الشبكة مثل غياب المفتاح، فلا تدخل عدّ الطلبات. استعمل هذه السطور المقيّدة، لا access logs للمصدر المحتوية على المفتاح داخل المسار.
8. أرفق في وصف PR الجدول الفعلي التالي؛ القيم الآن **غير منفذة**:

| UTC / commit | endpoint / league | HTTP | events أو rows | cache أول/ثاني | diagnostic | source requests في الساعة | عدد الملفات / خارج الويب |
|---|---|---|---|---|---|---|---|
| لم ينفذ | جميع ما سبق | — | — | — | — | — | — |

## قيود المصدر المعروفة (تذكر في كل PR)

- المباراة المؤجلة خارج تواريخ وحدتها الأصلية قد لا تظهر في يومها الجديد.
- التجميد بعد يومين لا يضمن ألا يضيف المزوّد مباريات لاحقاً؛ إلغاء التجميد الإداري بعد دليل وتصريف العمال مسؤولية المشغّل، لا حذف دوري آلي.
- الوحدة الفارغة تُحدّث كل ساعة؛ قد يظل اليوم/الجولة فارغاً حتى ساعة بعد نشر الجدول.
- TheSportsDB: المفتاح المجاني موجّه للتطوير؛ ESPN واجهة غير موثقة؛ Highlightly له شروطه وحصصه. على المالك مراجعة الشروط قبل الاعتماد العام الدائم واختيار خطة مناسبة؛ لا اشتراك تلقائي هنا.
- لا دليل نهائي لتجميد ترتيب موسم، ولا جلب حالة مباريات لبطولة غير مسموحة. لا ادعاء أن كل بطولات الترتيب ذات مباراة جارية معروفة إذا لم يزر أحد جدول المباريات.
