# 🛰️ وسيط البث المباشر — دليل النشر (مجاني 100%)

الوسيط القديم (Deno) أوقفته الشركة لتجاوز حد الاستخدام (`USAGE_EXCEEDED`) لأن البث
يستهلك النطاق الترددي بسرعة. الحل: **Cloudflare Workers** — مجاني ولا يحاسب على
النطاق الترددي إطلاقاً (مناسب للفيديو تماماً).

## ✅ نشر الوسيط الجديد على Cloudflare (3 دقائق)

### الطريقة الحديثة — Workers Builds الموصول بالمستودع (الأفضل)

لو ربطت مستودع GitHub بخدمة Worker في Cloudflare (Workers & Pages → Create → استيراد من GitHub):

1. تأكد أن ملف **`wrangler.jsonc`** موجود في جذر المستودع (أضفناه لك — يحدد `main: proxy/worker.js`)
2. ارفع أي تحديث للمستودع → ستبني Cloudflare وتنشر الوسيط **تلقائياً**
3. بنية الإعداد:
   - Build command: `npm run build` (يبني الموقع — لا يضر)
   - Deploy command: `npx wrangler deploy` (ينشر الوسيط من `proxy/worker.js`)

> بدون `wrangler.jsonc` يفشل النشر بخطأ "Could not resolve entry point" — هذا هو الملف الذي يحل المشكلة.

### الطريقة اليدوية (بديل)

- من لوحة التحكم اختر **Workers & Pages** (القائمة الجانبية)
- اضغط **Create** → اختر **Create Worker**
- أعطه اسماً مثل `serverproject` → اضغط **Deploy**
- اضغط **Edit code** → امسح محتوى الملف الظاهر، والصق كامل محتوى **`worker.js`** الموجود بجانب هذا الملف
- اضغط **Deploy** (أعلى اليمين)

### 4) خذ رابط الوسيط
- ستجد الرابط أعلى الصفحة بهذا الشكل:
  `https://stream-proxy.اسمحسابك.workers.dev`
- افتحه في المتصفح — يجب أن ترى صفحة خضراء: **"وسيط البث يعمل بنجاح"** ✅

### 5) فعّله في الموقع (اختر إحدى الطريقتين)

**الطريقة أ — تجربة فورية بدون تعديل كود (للاختبار):**
افتح موقعك وأضف هذا البارامتر:
```
https://ahmedlasheenrespicare-png.github.io/serverproject/?proxy=https://stream-proxy.اسمحسابك.workers.dev
```
(يُحفظ تلقائياً لجلسة المتصفح الحالية)

**الطريقة ب — تفعيل دائم (الموصى بها):**
افتح `src/components/LivePlayer.tsx` وابحث عن السطر:
```ts
// "https://YOUR-WORKER-NAME.YOUR-SUBDOMAIN.workers.dev",  ← ألصق رابط الوسيط الجديد هنا
```
احذف علامتي التعليق وضع رابطك بدلاً منه، ثم ارفع التحديث.

## 🔐 تقييد الوسيط (مهم — تغيير في النسخة الحالية)

الوسيط الآن **لا يخدم إلا نطاق موقعك** لمنع استخدامه كوسيط مفتوح (سرقة النطاق الترددي):

- قائمة النطاقات المسموحة في أعلى `worker.js`:

```js
const ALLOWED_ORIGINS = [
  "https://ahmedlasheenrespicare-png.github.io",
];
```

- الطلبات القادمة من موقع آخر تُرفض بـ `403 ORIGIN_NOT_ALLOWED`.
- `localhost` ونطاقات المعاينة `*.e2b.app` مسموحة للتطوير.
- **حماية إضافية (جديدة):** عناصر `<video>` و`<audio>` العابرة للنطاق **لا ترسل رأس `Origin` إطلاقاً**
  (وضع `no-cors`)، لذلك يُفحَص رأس `Referer` أيضاً: أي طلب بلا `Origin` وبـ `Referer` من موقع آخر
  يُرفض بـ `403 REFERER_NOT_ALLOWED`. الطلبات بلا `Origin` وبلا `Referer` (مشغّل أصلي، `curl`، فحص يدوي)
  تبقى مسموحة، ويُضبط حجم استخدامها بـ Rate Limiting من لوحة Cloudflare.

> **عند نقل الموقع لنطاق مخصص** (مثل `example.com`) أضِفه إلى `ALLOWED_ORIGINS` ثم أعد نشر الوسيط،
> وإلا سيتوقف البث عبر الوسيط بخطأ 403.

**الحد من الاستهلاك:** فعّل Rate Limiting من لوحة Cloudflare (Workers → الإعدادات) للحد من أي إساءة استخدام.
> الحماية بالكود لا تكفي وحدها: طلب واحد بلا `Origin` وبلا `Referer` يمرّ بطبيعته (لأن المتصفحات لا ترسل
> أي منهما في بعض الحالات الشرعية)، فالقاعدة على Cloudflare هي خط الدفاع الثاني.

## 🎭 بصمة المشغّل — `?smpua=smarters` (User-Agent الخاص بـ IPTV Smarters/VLC)

كثير من لوحات Xtream وشبكات CDN **تحجب متصفحات الويب** وتسمح فقط لمشغلات IPTV
المعروفة، فترد `403`/`406` على طلب قائمة `.m3u8` حتى لو كان الاشتراك سليماً.
والمتصفح يعتبر `User-Agent` رأساً **محظوراً**: لا `fetch` ولا `XMLHttpRequest` ولا
`xhrSetup` في `hls.js` تستطيع تغييره — الوسيط وحده يقدر.

لذلك يرسل مشغّل الموقع (`#xtream` في الصفحة الرئيسية) اسم البصمة للوسيط، والوسيط
يترجمه إلى القيمة الحقيقية:

```
https://<الوسيط>/h/srv.example/live/u/p/1.m3u8?token=abc&smpua=smarters
  ↓  الوسيط يرسل للسيرفر الأصلي
GET https://srv.example/live/u/p/1.m3u8?token=abc
User-Agent: iptv_smarters_player_lite/1.4.2 VLC/3.1.2 LibVLC/3.1.2
```

ما يفعله `worker.js` (ومثله `proxy.php` في جذر المستودع):

- **قائمة مغلقة:** `UA_PRESETS` لا تحتوي إلا `smarters`. أي قيمة أخرى تُتجاهل ويُرسل
  `User-Agent` المتصفح كما كان — فلا يتحول الوسيط إلى أداة تمويه عشوائية.
- **المعامل لا يتسرب:** `smpua` يُحذف من الاستعلام قبل توجيه الطلب (`upstreamSearch`)،
  فلا يصل للسيرفر الأصلي ولا يُفسد رابطاً موقّعاً.
- **بصمة واحدة لكل البث:** القائمة المعاد كتابتها تحمل `smpua` في كل مقطع وقائمة
  فرعية ومفتاح فك تشفير (`toProxyPath`) — وإلا طلب السيرفر جلسة جديدة لكل مقطع.
- **تحويل 302 يُتابَع** (`redirect: "follow"`) بنفس الرؤوس، فتبقى البصمة و`Range`
  محفوظتين بعد التحويل.
- **معاملات جلسة القائمة:** التوكن الموجود في رابط القائمة (مثل `?token=…`) يُنسخ
  للروابط الفرعية **على نفس المضيف** التي لا تحمل استعلاماً خاصاً (`withSession`)،
  ولا يُضاف لأي رابط له توقيعه الخاص.
- **`Range` يمر كما هو** وحالة الرد (بما فيها `206`) تعود كما هي.

> ⚠️ **البصمة لا تعمل قبل نشر الوسيط الجديد.** الوسيط القديم يتجاهل `smpua` كأي
> معامل غير معروف ويبقى السلوك كما كان (لا ينكسر شيء)، لكن السيرفر الذي يحجب
> المتصفحات سيستمر في الرفض. الحل: نشر هذا الملف (`npx wrangler deploy`) أو الاعتماد
> على `/proxy.php` في الاستضافة التي تشغّل PHP.

## 🌐 نفق ngrok (البث المعاد — قناة 786431)

البث المعاد يبثّ من جهاز صاحب الموقع عبر نفق ngrok، ونفق ngrok المجاني يعرض
**صفحة تحذير HTML** («You are about to visit …») لأي طلب يبدو قادماً من متصفح
بدل تمرير ملف البث — فيستلم `hls.js` صفحة HTML ويظهر «تعذر تشغيل القناة» بلا سبب واضح.

العلاج المطبَّق في `worker.js`:

- ترويسة `ngrok-skip-browser-warning: true` تُضاف **عند التوجيه إلى مضيفات ngrok فقط**
  (بقية السيرفرات لا تستلمها).
- لو وصلت صفحة التحذير رغم ذلك، يعيد الوسيط خطأ JSON صريحاً للمشغل
  `{"error":"NGROK_WARNING_PAGE"}` بحالة `502` بدل تمرير HTML إلى المشغل.
- صفحة «النفق غير متصل» (`ERR_NGROK_3200`) تُمرَّر كما هي — السبب في جهاز البث لا في الوسيط.

> ⚠️ **هذا الإصلاح لا يعمل على الموقع قبل نشر الوسيط.** بعد أي تعديل على `worker.js`
> إما أن ينشره Cloudflare Workers Builds تلقائياً بعد الدفع إلى `main`، أو يدوياً:
> ```bash
> npx wrangler deploy
> ```
> وللتأكد أن الوسيط **المنشور** يتخطى صفحة التحذير فعلاً:
> ```bash
> npm run check:proxy        # أو: node scripts/check-proxy.mjs
> ```

## ⚠️ إن فشل بناء Cloudflare Workers (Workers Builds)

فحص **Workers Builds: serverproject** كان **فاشلاً قبل هذه التعديلات أيضاً** (على `main` وليس على تغييرات
جديدة فقط)، بينما ملف الوسيط نفسه سليم ومقبول للنشر: تم التحقق محلياً بـ

```bash
npx wrangler deploy --dry-run --outdir /tmp/wrangler-out
# Total Upload: 9.78 KiB / gzip: 3.53 KiB — بلا أخطاء
```

أي أن المشكلة في **إعداد المشروع على Cloudflare** وليس في `worker.js`. الخطوات:

1. **افتح سجل البناء** من الرابط في تعليق البوت على الـ PR (أو من)
   `Cloudflare Dashboard → Workers & Pages → serverproject → Deployments → Builds → آخر بناء → Logs`.
2. تحقّق من الإعدادات الشائعة:
   - Build command: `npm run build` — إن كان مختلفاً أو فارغاً، اجعله كذلك (أو `exit 0` لو أردت نشر الوسيط فقط).
   - Deploy command: `npx wrangler deploy`
   - Node version: المشروع يحتاج Node 20.19+ (ثبّتنا `22` في `.node-version`).
   - صلاحية التوكن/الحساب: إن ظهر `Authentication error` أو `account not found` أعد ربط حساب Cloudflare بالمستودع.
3. **مسار بديل مضمون لا يعتمد على البناء التلقائي** (وهو الأسرع الآن):
   ```bash
   npx wrangler deploy        # من جهازك داخل مجلد المشروع
   ```
   أو انسخ محتوى `proxy/worker.js` والصقه في `Dashboard → Worker → Edit code → Deploy`.
4. بعد النشر، افتح صفحة حالة الوسيط وتأكد من التعديل: يجب أن ترد القناة `http` عبر `/x/…`
   ويرفض الطلبات القادمة بـ `Referer` من موقع آخر (`403`).

## 🧪 اختبار يدوي (اختياري)

جرّب هذه الروابط في المتصفح مباشرة:

| الغرض | الرابط |
|---|---|
| صفحة الحالة | `https://رابط-الوسيط/` |
| فحص سريع | `https://رابط-الوسيط/health` |
| رابط كامل (المسار الذي يستخدمه مشغل الاشتراك) | `https://رابط-الوسيط/?u=<الرابط-مُرمَّزاً>` |
| قناة العربية | `https://رابط-الوسيط/h/live.alarabiya.net/alarabiapublish/alarabiya.smil/playlist.m3u8` |
| قناة MBC 1 | `https://رابط-الوسيط/live/bitmovin-mbc-1-na/eec141533c90dd34722c503a296dd0d8/index.m3u8` |
| سيرفر بلا TLS (مهم) | `https://رابط-الوسيط/x/host:port/live/user/pass/1.m3u8` |
| البث المعاد (ngrok) | `https://رابط-الوسيط/h/passive-rotunda-deduct.ngrok-free.dev/my_restream.m3u8` |
| فحص آلي للمسار كاملاً | `npm run check:proxy` |

لو فتح ملف قائمة تشغيل نص فيه روابط تبدأ بـ `/h/...` (أو `/x/...` لسيرفرات `http`) فالوسيط يعمل بشكل صحيح.

**ملاحظة إصلاح مهمة:** إعادة كتابة قوائم m3u8 تحفظ الآن **بروتوكول الرابط الأصلي**:
روابط `http://` تُحوَّل إلى `/x/` وروابط `https://` إلى `/h/`. قبل ذلك كانت كلها تُحوَّل إلى `/h/`
(أي https إجبارياً) فيتوقف البث عند أول مقطع على السيرفرات التي لا تدعم TLS.
